# v1.0 Routing Evaluation

## Outcome: not run

The live comparison of legacy `auto`, deterministic rules and the local Ollama classifier was not run in the implementation environment on 2026-10-16.
No provider calls were made and no evaluation spend was incurred.

The required run inputs were unavailable:

- `GROQ_API_KEY`, `OPENROUTER_API_KEY` and `SPILLWAY_EVAL_KEY` were unset.
- Ollama was not installed, so no classifier model tag or digest could be recorded.
- The two independent raters required by the protocol had not been recruited, and no blinded score sheets or adjudications were available.
- No `spillway catalog` output was captured, so candidate model references and prices were not selected or verified.

The environment had Go `go1.27.2 windows/amd64`.
The evaluation seed, Ollama version and digest, candidate references and prices, catalog source/date, cost-source shares, and gate verdicts are unavailable because the run did not happen.
They must not be inferred from prior snapshots or the offline mock evaluation.

The v2 prompt corpus remains committed at [evaluation-prompts.v2.json](../examples/evaluation-prompts.v2.json).
There are no live run metrics, completions, blind key, ratings, or `eval-report` output to publish.
Live configs were not pinned because doing so before selecting candidates from current catalog output would encode unverified model references and prices.

To complete this non-blocking evaluation, the owner should choose candidates from fresh `spillway catalog` output, attest that any Groq free-tier account has no paid plan or use an eligible OpenRouter `:free` model, and pin an Ollama classifier tag and digest.
Configure three independent Spillway processes with a combined daily budget no greater than $5, run a 10-prompt pilot, and project the full-run cost.
Reduce repeats from three to two if the projection exceeds $4.
If a Spillway budget truncates an arm, record that arm as inconclusive rather than tuning the run.
Then have two independent raters score blinded answers and adjudicate severe failures before unblinding.
Publish the exact candidate references, declared prices and catalog source/date, environment versions, seeds, cost-source shares and complete `eval-report` output here.
Keep completions and `blind-key.json` out of version control.

This outcome does not change runtime routing defaults.
