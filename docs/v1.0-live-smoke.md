# v1.0 live-provider smoke checks

Date assessed: 2026-10-16
Version: pre-release source at `v1.0-release`
Environment: Windows 11 amd64

These optional checks require live provider credentials or external runtime setup.
They were not run during this release audit.
No requests were made for these seven smoke checks.
The separate live routing evaluation pilot and partial run are documented in [the evaluation record](v1.0-routing-evaluation.md).

| Check | Status | Reason |
|---|---|---|
| Groq chat and streaming through the OpenAI Python and Node SDKs | Not run | Requires a user-provided Groq key and live provider requests. |
| Gemini chat, streaming and tools | Not run | Requires a user-provided Gemini key and live provider requests. |
| OpenRouter `:free` chat and streaming | Not run | Requires a user-provided OpenRouter key and live provider requests. |
| Local Ollama chat, streaming and classifier rules route | Not run | Requires a locally running Ollama service and pinned model. |
| Cross-provider spillover after a deliberately invalid key | Not run | Requires a configured live provider and would make an upstream request. |
| Docker with Linux `--network host` and host Ollama | Not run | This audit environment is Windows; the scenario is Linux-specific. |
| `spillway catalog` against configured providers | Not run | Requires configured provider credentials and live catalog requests. |

These checks remain unverified and are not evidence that provider integrations work against current live services.
The offline provider fixtures and CI checks are separate evidence.
This record covers the optional checks listed in the v1.0 release plan; RC artifact verification is a separate required gate.
