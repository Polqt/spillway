# v0.5 Routing Evaluation

## Prompt set format

Prompt sets are UTF-8 JSON objects with `version: 1` and a `prompts` array.
Each prompt has a unique `id`, a lowercase `category`, a `difficulty` of `simple`, `moderate`, or `hard`, and non-empty prompt text up to 32 KiB.
Optional `settings` accepts `temperature`, `top_p`, `max_tokens`, `seed`, and `stop`.
Unknown fields and settings are rejected.
The example corpus is [evaluation-prompts.v1.json](../examples/evaluation-prompts.v1.json).

## Offline run

The fake provider path uses Spillway's deterministic `mock` provider and does not require provider credentials or network access beyond loopback.
Keep this config's `store:` setting absent so evaluation traffic does not add rows to a usage database.

```powershell
go run ./apps/spillway serve -config examples/config.eval.yaml
```

In a second terminal, run the current auto arm:

```powershell
go run ./apps/spillway eval -dataset examples/evaluation-prompts.v1.json -arms current-auto=auto -repeats 2 -seed 20261015 -prices examples/evaluation-prices.mock.json -out .scratch/evaluation/current-auto
```

The runner randomizes arm order within every prompt/repeat pair, requests streaming usage, and records the random seed.
To compare modes with different server configurations, run one Spillway instance per arm and pass each base URL after `@`, for example `-arms current-auto=auto@http://127.0.0.1:8080,rules=auto@http://127.0.0.1:8081`.
The evaluator randomizes arm order while sending each paired prompt to the endpoint configured for that arm.
Comparative runs must use the same prompt set, settings, prices, repeat count, and candidate configuration.

## Artifacts and scoring

`metrics.json` contains per-trial cost source and timing plus aggregate p50/p95 latency and time-to-first-token, mean estimated cost, cost coverage, and source shares.
Aggregates are reported by arm, difficulty, and category, with overall rows.
`answers.jsonl` contains completions with opaque answer IDs and no arm name.
`blind-key.json` maps answer IDs to arms and must be withheld from scorers until scoring is complete.
`scores.csv` is a blank scoring sheet for correctness, completeness, instruction following, and severe correctness failure.
Score each response independently before opening the key, and adjudicate severe failures while still blinded.
After filling the CSV, run `go run ./apps/spillway eval-score -run .scratch/evaluation/current-auto` to write quality and severe-failure rates by arm, difficulty, and category.
Treat evaluation output as sensitive local data because it contains prompts and model completions.
It is separate from Spillway's normal logs and usage store.

The harness prints neither prompt text nor completion text to normal logs or the terminal.
The API's production usage records contain metadata only, but disable `store:` during evaluation to avoid mixing evaluation traffic into operational usage summaries.

## Manual live-model path

Use a dedicated evaluation config for each arm, with only the intended provider candidates, exact model prices, a local API key, no `store:`, and cache disabled.
Keep provider settings identical across arms except for the routing mode under evaluation.
Start each Spillway instance on its own loopback port, then run `spillway eval` with one `name=model@endpoint` entry per arm.
Provide the local key through `-api-key-env SPILLWAY_EVAL_KEY`; never put a real key in the prompt set, prices file, command line, or artifacts.
Use fixed seeds and generation settings where providers honor them, run enough repeats to represent normal variance, and retain the emitted seed and environment record with the results.
Do not run live-provider quality evaluations in CI.

Ratings are blinded by answer ID, not by a claim that model style cannot reveal model identity.
Use at least two independent raters for promotion decisions and adjudicate disagreements about severe failures before unblinding.
The agreed promotion gates and paired prompt-level bootstrap procedure are in [ADR 0014](adr/0014-v0.5-evaluation-and-difficulty-routing.md).
