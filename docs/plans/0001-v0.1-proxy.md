# v0.1 Proxy

Status: complete; shipped in v1.0.0; approved (2026-10-14; all open questions resolved with their recommended defaults; amended 2026-10-14 after grilling, see Decisions; layout amended 2026-10-14 by ADR 0004: binary entry in `apps/spillway`, CLI in `internal/cli`, all tests under `tests/`)
Milestone: v0.1

## Goal

Spillway is a single Go binary that serves an OpenAI-compatible `/v1/chat/completions` (streaming and non-streaming) and `/v1/models` on `127.0.0.1:8080`.
A request naming a model reference (`provider/model`) is proxied unchanged to Groq, OpenRouter, Ollama or Gemini, or to a built-in deterministic mock provider, with a named local key required on every listen address, a `Host` check on loopback, and no secret ever reaching logs, errors or responses.
The config loader, `spillway check` and `spillway version` exist, and `make check` passes on Windows, Linux and macOS.

## Scope

In:
- `go.mod` (module `github.com/Polqt/spillway`, `go 1.26`), dev tools pinned with `tool` directives in `tools/go.mod`, `.golangci.yml`, `.gitattributes`, and a Makefile with `build`, `test`, `lint`, `check`, `run`, `mock`, `vuln`, `cover`.
- `internal/cli` with `serve`, `check` and `version` subcommands, standard library `flag` parsing, and the wiring from config to providers.
- `internal/redact`: the `Secret` type, a `Scrubber` for arbitrary strings, and a scrubbing `slog.Handler` wrapper.
- `internal/config`: YAML loading with `${ENV}` expansion, strict decoding, named local keys, validation, redacted printing.
- `internal/providers`: the `Provider` and `Stream` interfaces, OpenAI-format request/response/chunk types, `ModelRef`, shared error kinds, a bounded SSE reader, and the provider registry (`Set`).
- `internal/providers/openaicompat`: one client configured per preset (Groq, OpenRouter, Ollama).
- `internal/providers/gemini`: Gemini through its OpenAI-compatible endpoint.
- `internal/providers/mock`: deterministic, offline, streaming-capable, with error-simulating models.
- `internal/fakenet`: an in-memory `net.Listener` and dialer over `net.Pipe`, so HTTP timeouts can be tested under `testing/synctest`.
- `internal/api`: `POST /v1/chat/completions`, `GET /v1/models`, `GET /healthz`, the loopback `Host` check, Bearer auth with local keys that resolves the client app, OpenAI error shape, `x-spillway-provider` and `x-spillway-model` headers, body limit, stream-safe timeouts, disconnect propagation.
- `examples/config.yaml` (env placeholders only) and `examples/config.mock.yaml` (no real keys).
- ADR 0001 for the Gemini endpoint choice and ADR 0002 for where the dev tools are pinned; ADR 0003 (accepted) requires a local key on every listen address and the loopback `Host` check.

Out:
- Tiers (user-named, `[a-z0-9-]`), spillover across providers on 429 and errors, quota tracking, circuit breakers: v0.2.
- Virtual models (`auto` and `spillway/<tier>`), capability detection, `x-spillway-route`: v0.3.
- SQLite usage logs (including per-client-app usage), budgets, cache, dashboard, `logging.bodies`, `x-spillway-cache`: v0.4.
- `/v1/embeddings`: not in the v0.1 milestone text; deferred (open question 7).
- Mistral, Anthropic and OpenAI adapters: later milestones.
- Model list caching: v0.2, together with quota state.
- `spillway init`, GoReleaser, Docker image: v1.0.
- Encrypted at-rest key storage (encrypted file or OS keychain): after v1.0, behind an ADR (CONTEXT.md section 9). v0.1 reads provider keys from env vars only; local keys come from env vars or, for fake test keys only, literals.

## Design

### Decided inputs

These are settled in AGENTS.md, CONTEXT.md, `docs/CODING_STANDARDS.md`, `GLOSSARY.md` and the ADRs and are not reopened here:
Go 1.26+ as the `go` directive; `net/http` `ServeMux` method patterns, no chi; `go.yaml.in/yaml/v3` for YAML; `ChatStream` returns a pull-based `Stream`; one `openaicompat` package with presets plus `gemini` and `mock` packages; golangci-lint and govulncheck pinned with `tool` directives (in `tools/go.mod`, ADR 0002) and run with `go tool`; provider keys from env vars only; a local key is required on every listen address and loopback listens check `Host` (ADR 0003).

### Toolchain and module

`go.mod` declares `go 1.26`, the oldest supported release now that Go 1.27 is out; it gives `testing/synctest`, `t.Context()`, `sync.WaitGroup.Go` and the `tool` directive.
The local toolchain is go1.27.2 windows/amd64 (updated 2026-10-14), which builds a 1.26 module.

Pinned tools (each at least two weeks old on 2026-10-13):
- `github.com/golangci/golangci-lint/v2/cmd/golangci-lint` v2.13.2 (2026-08-27; v2.14.0 exists and can be adopted later).
- `golang.org/x/vuln/cmd/govulncheck` v1.8.0 (2026-09-08; v1.9.0 is two days old and not yet eligible).

Both pinned tools declare `go 1.26.0` in their own `go.mod`, which matches the root directive.
golangci-lint v2.13.2 also brings about 226 requirements, which would join the binary's module graph, where minimal version selection can raise the versions of modules the binary links (for example `go.yaml.in/yaml/v3`, `golang.org/x/sys`).
Verified on this machine in a scratch repo: `go get -tool golang.org/x/vuln/cmd/govulncheck@v1.8.0` inside a separate `tools/go.mod` bumped only that file to `go 1.26.0`, left the root untouched, and `go tool -modfile=tools/go.mod govulncheck ./...` scanned the root module.
The plan therefore keeps the decided mechanism (the `tool` directive and `go tool`) but puts the tool directives in `tools/go.mod` and runs them with `go tool -modfile=tools/go.mod <tool>`, so the tools' requirements never raise the versions the binary links (ADR 0002).

`.golangci.yml` (v2 format) enables `govet`, `staticcheck`, `errcheck`, `errorlint`, `bodyclose`, `noctx`, `contextcheck`, `gosec`, `sloglint`, `ineffassign`, `unused`, and the `gofmt` formatter.
golangci-lint v2 reports formatter violations from `golangci-lint run`, which is the "gofmt check" in `make lint`.
`gosec` exclusions, if any, are written in `.golangci.yml` with a one-line reason each, never as blanket disables.
`sloglint` is configured for key-value pairs with snake_case keys, matching the stable keys rule in CODING_STANDARDS.md.

Windows line endings: Git for Windows may check out `.go` files with CRLF, which gofmt reports as unformatted.
T1 adds `.gitattributes` with `* text=auto eol=lf` so lint results do not depend on the platform.

### Makefile

GNU make 4.4.1 from scoop runs recipes through `cmd.exe` when no `sh.exe` is on PATH, which is the case from PowerShell on this machine (verified: `$(SHELL)` reported `sh.exe` but `$$0` was echoed literally).
Therefore every recipe line is a single plain command with no shell syntax (no `$$(...)`, `&&`, `test`, redirection or `VAR=x cmd`).
Environment for a command is set with target-specific `export`, which make passes through the process environment under any shell.
Checks that would need a shell live in the tools themselves: golangci-lint fails on format issues, and `go mod tidy -diff` fails on module drift.

```make
GO      ?= go
TOOL    := $(GO) tool -modfile=tools/go.mod
EXE     := $(shell $(GO) env GOEXE)
BIN     := bin/spillway$(EXE)
VERSION ?= dev
LDFLAGS := -s -w -X github.com/Polqt/spillway/internal/cli.version=$(VERSION)
RACE    ?= $(if $(filter 1,$(shell $(GO) env CGO_ENABLED)),-race,)

build: export CGO_ENABLED=0
build:   ; $(GO) build -trimpath -ldflags "$(LDFLAGS)" -o $(BIN) ./apps/spillway
test:    ; $(GO) test $(RACE) -count=1 ./...
lint: export CGO_ENABLED=0
lint:
	$(GO) mod tidy -diff
	$(GO) -C tools mod tidy -diff
	$(GO) build ./...
	$(TOOL) golangci-lint config verify
	$(TOOL) golangci-lint run ./...
check: lint test
run:  build ; $(BIN) serve -config examples/config.yaml
mock: build ; $(BIN) serve -config examples/config.mock.yaml
vuln:    ; $(TOOL) govulncheck ./...
cover:
	$(GO) test -count=1 -coverprofile=coverage.out ./...
	$(GO) tool cover -html=coverage.out -o coverage.html
```

The block is the intended shape, not final text; the implementer writes it with tabs and `.PHONY`.
`lint` exports `CGO_ENABLED=0`, so its `go build ./...` proves the hard rule "`CGO_ENABLED=0 go build ./...` must always work" on every `make check`; this is the check that the release build is cgo-free.
Target-specific variables apply to `lint` and its prerequisites only, so the sibling `test` target still sees the ambient `CGO_ENABLED`.
`build` also exports `CGO_ENABLED=0`, so the shipped binary is always cgo-free, and T1 acceptance confirms it with `go version -m`.
`RACE` is `-race` when `go env CGO_ENABLED` is `1` and empty otherwise; `go env CGO_ENABLED` reports `0` when no C compiler is on PATH, so this degrades cleanly on machines without gcc.
Verified on this machine: `go env CGO_ENABLED` is `1`, gcc 15.2.0 is at `C:\Users\poyhi\scoop\apps\gcc\current\bin\gcc.exe`, a scratch `go test -race` passed, and `CGO_ENABLED=0 go test -race` fails with `-race requires cgo`.
Linux and macOS have cgo by default, so the race detector runs there too; `make test RACE=` forces it off.
The race runtime is test-only and never enters the binary.
`VERSION` defaults to `dev` and is overridden as `make build VERSION=v0.1.0`; deriving it from `git describe` is left to the v1.0 GoReleaser work because it needs shell redirection in repos without tags.
`bin/spillway$(EXE)` is invoked with forward slashes, which `CreateProcess` accepts when make takes its direct-exec path; T1 acceptance checks `make build` and `make mock` from PowerShell, cmd and Git Bash.
`govulncheck` reported 46 standard library findings for go1.26.0; the toolchain was updated to go1.27.2 to clear them, and T1 re-runs `make vuln` to confirm. `vuln` is not part of `check`.

### internal/redact

```go
type Secret struct{ v string }

func NewSecret(s string) Secret
func (s Secret) Reveal() string                // the only accessor; grep-able at every call site
func (s Secret) IsZero() bool
func (s Secret) String() string                // "[REDACTED]", or "" when zero
func (s Secret) GoString() string              // `redact.Secret("[REDACTED]")`
func (s Secret) Format(f fmt.State, verb rune) // every verb, including %x and %q, prints the redacted form
func (s Secret) MarshalText() ([]byte, error)  // "[REDACTED]"; used by YAML encode, slog text, JSON map keys
func (s *Secret) UnmarshalText(b []byte) error // used by YAML decode
func (s Secret) MarshalJSON() ([]byte, error)  // "\"[REDACTED]\""
func (s Secret) LogValue() slog.Value          // slog.StringValue("[REDACTED]")

type Scrubber struct{ /* strings.Replacer over known secret values */ }

func NewScrubber(secrets ...Secret) *Scrubber
func (s *Scrubber) Scrub(text string) string
func (s *Scrubber) Error(err error) error // Error() is scrubbed; Unwrap keeps errors.Is and errors.As working

func NewHandler(next slog.Handler, s *Scrubber) slog.Handler
```

`MarshalText` makes the YAML library print `[REDACTED]` when `check` dumps the config, so redacted printing needs no custom printer and a config can never be written back to disk with real keys.
The YAML library honours `encoding.TextMarshaler` and `TextUnmarshaler` for scalars, so `redact` does not import YAML.
`Scrubber` replaces every occurrence of every configured secret (longest first, empty secrets ignored) with `[REDACTED]`; it is applied to upstream error text, to error messages before they reach clients or logs, and in the logging handler.
`NewHandler` scrubs the record message and every string, error and `fmt.Stringer` attribute, recursing into groups, as defence in depth behind the `Secret` type.
A known limitation is documented in the package comment and tested: `fmt` cannot call methods on unexported struct fields, so a `Secret` stored in an unexported field of a struct printed with `%+v` would print raw.
The rule is that `Secret` fields are always exported, and `config` has a test that prints the whole config.
Rejected alternative: a plain `string` plus "remember to redact" at call sites, which fails open.

### internal/config

Dependency: `go.yaml.in/yaml/v3` pinned at **v3.0.5** (released 2026-07-26, 79 days old, declares `go 1.16`).
It is the maintained continuation of the archived `gopkg.in/yaml.v3` with the same API, and golangci-lint v2.13.2 already uses the same version.
v3.0.4 (2025-06-29) was rejected because v3.0.5 is past the two-week rule and is the current maintained release.

Schema accepted in v0.1:

```yaml
server:
  listen: "127.0.0.1:8080"        # default
  api_keys:                        # local keys; at least one is required on every listen address (ADR 0003)
    - "${SPILLWAY_KEY}"            # plain form: named key-1, key-2, ... by list position
    - name: cursor                 # named form: the name identifies the client app
      key: "${SPILLWAY_CURSOR_KEY}"
logging:
  level: info                      # debug | info | warn | error
providers:
  groq:       { api_key: "${GROQ_API_KEY}" }
  openrouter: { api_key: "${OPENROUTER_API_KEY}" }
  gemini:     { api_key: "${GEMINI_API_KEY}" }
  ollama:     { base_url: "http://localhost:11434" }
  mock:       {}
  # every provider also accepts: base_url (override), timeout (Go duration, default 120s)
```

```go
type Config struct {
    Server    Server
    Logging   Logging
    Providers map[string]Provider // keys validated against the known names
}
type Server struct {
    Listen  string
    APIKeys LocalKeys `yaml:"api_keys"`
}
func (s Server) Loopback() bool // true when the listen host is "localhost" or a loopback IP

// LocalKey is one local key and the client app name it identifies.
type LocalKey struct {
    Name string        `yaml:"name"`
    Key  redact.Secret `yaml:"key"`
}
// LocalKeys decodes each entry from a plain string or a {name, key} mapping.
type LocalKeys []LocalKey
func (ks *LocalKeys) UnmarshalYAML(n *yaml.Node) error

type Provider struct {
    APIKey  redact.Secret
    BaseURL string
    Timeout time.Duration
}

func Load(path string, lookupEnv func(string) (string, bool)) (Config, error)
func Parse(data []byte, lookupEnv func(string) (string, bool)) (Config, error)
func (c Config) Secrets() []redact.Secret // every provider key and every local key
func (c Config) WriteRedacted(w io.Writer) error
```

Loading pipeline: read the file (capped at 1 MiB), parse into a `yaml.Node`, expand `${NAME}` in scalar values only, reject reserved future sections, re-encode the node, decode with `KnownFields(true)`, apply defaults, validate.
Expansion runs on parsed scalar nodes, not on raw text, so an env value containing `"`, `:` or a newline cannot change the YAML structure; raw-text expansion was rejected for that reason.
Only the `${NAME}` form is expanded, with `NAME` matching `[A-Za-z_][A-Za-z0-9_]*`; bare `$NAME` is left alone because keys and URLs may contain `$`; `$${` is a literal `${`.
An unset or empty variable is an error naming the variable, the YAML path and the line, never a value: `config: providers.groq.api_key (line 7): environment variable GROQ_API_KEY is not set` (open question 2).
An unterminated `${` or an invalid name is an error.
`lookupEnv` is injected (`os.LookupEnv` in `main`) so config tests can run with `t.Parallel()`; `internal/cli` tests use `t.Setenv` as CODING_STANDARDS.md prefers.

Local key decoding:
`UnmarshalYAML` is defined on the slice type `LocalKeys`, not on `LocalKey`, because the generated name `key-N` needs the entry's position, which a per-element unmarshaller cannot see.
It requires a sequence node and walks it: a scalar entry becomes `LocalKey{Name: "key-<i+1>", Key: NewSecret(value)}`, and a mapping entry is read key by key, accepting only `name` and `key` (both required), so an unknown field is still an error even though `node.Decode` does not inherit `KnownFields(true)`.
Any other node kind (a nested sequence, an alias, null) is an error naming `server.api_keys[i]`.
Position counts every entry, so in `["${A}", {name: ci, key: "${B}"}, "${C}"]` the plain entries are `key-1` and `key-3`.
`${NAME}` expansion has already run on every scalar, so both forms take env placeholders.
A custom unmarshaller was chosen over two config fields (`api_keys` and `named_api_keys`) because the user asked for one list that accepts both forms, and over a `yaml:",inline"` trick because the scalar form cannot be expressed with struct tags.
`WriteRedacted` always prints the mapping form, `- name: key-1` with `key: '[REDACTED]'`, so the printout shows which client app each generated name belongs to without revealing a key.

Validation (every error names the YAML path and says how to fix it, and never contains a key value):
- Unknown fields are errors (strict decoding, open question 3).
- `tiers`, `router`, `budgets`, `cache` are recognised and rejected with `config: "tiers" is not supported until v0.2; remove it` (v0.3 for `router`, v0.4 for `budgets` and `cache`), instead of a generic unknown-field message. Tier names will be user-chosen `[a-z0-9-]` when `tiers` arrives in v0.2; v0.1 does not parse them.
- `server.listen` defaults to `127.0.0.1:8080`, must parse with `net.SplitHostPort`, and the port must be 0 to 65535.
- Loopback means host `localhost` or an IP for which `IsLoopback()` is true; an empty host (`:8080`), `0.0.0.0`, `::` or any other address is non-loopback. `Server.Loopback` exposes this so `internal/cli` can enable the `Host` check.
- `server.api_keys` must list at least one local key on every listen address, loopback included (ADR 0003): `config: server.api_keys must list at least one local key, even on loopback (ADR 0003); add one such as "${SPILLWAY_KEY}"`. `serve` and `check` both go through this validation, so both refuse such a config.
- Each local key must be non-empty and contain no whitespace.
- Each local key name must match `[a-z0-9-]{1,64}`: lowercase so `client_app` values compare without case folding, and bounded so a name cannot flood a log line.
- Names must be unique across the list, including generated ones: an explicit `key-2` next to a plain second entry is a duplicate, and the error names both paths, for example `server.api_keys[3].name "key-2" duplicates server.api_keys[1]`.
- Two entries with the same key value are an error naming both paths and no value, because one key could then not resolve to one client app.
- At least one provider must be configured.
- Provider names must be one of `gemini`, `groq`, `mock`, `ollama`, `openrouter`; `spillway` and `auto` are reserved.
- `api_key` is required for groq, openrouter and gemini; optional for ollama (for an authenticating reverse proxy); rejected for mock.
- `base_url`, when set, must be an absolute URL with no userinfo, query or fragment; `https` is required except for ollama and loopback hosts, so a provider key never crosses a network in clear text.
- `timeout` must be positive and at most 30m.
- `logging.level` must be one of the four levels.

`WriteRedacted` encodes the validated config as YAML; `Secret` fields print `[REDACTED]`.

### internal/providers

The interfaces, as in CONTEXT.md section 10:

```go
type Provider interface {
    Name() string
    Models(ctx context.Context) ([]Model, error)
    Chat(ctx context.Context, req ChatRequest) (ChatResponse, error)
    ChatStream(ctx context.Context, req ChatRequest) (Stream, error)
}

type Stream interface {
    Recv() (ChatChunk, error) // io.EOF after the last chunk; any other error ends the stream
    Close() error             // releases the upstream connection; safe to call twice and after io.EOF
}
```

Every `Stream` implementation owns no goroutine: `Recv` reads the next SSE event from the response body on the caller's goroutine, and `Close` closes the body and cancels the per-request context.

Model references, a domain type so a provider name and an upstream model cannot be mixed up:

```go
type ModelRef struct{ Provider, Model string }
func ParseModelRef(s string) (ModelRef, error) // splits at the first "/", both halves non-empty
func (r ModelRef) String() string               // "provider/model"
```

The upstream model (the remainder after the first `/`) may contain more `/` or `:`, as in `openrouter/meta-llama/llama-3.1-8b-instruct:free` or `ollama/llama3.2:3b`.

Registry:

```go
type Set struct{ /* name -> Provider, sorted names; immutable after construction */ }
func NewSet(ps ...Provider) (*Set, error) // error on an empty set or duplicate names
func (s *Set) Lookup(name string) (Provider, bool)
func (s *Set) All() []Provider            // sorted by name
```

Request and response types:

```go
type ChatRequest struct {
    Model    string                     // upstream model, provider prefix already stripped
    Messages []Message
    Extra    map[string]json.RawMessage // every other top-level field, verbatim
}
type Message struct {
    Role    string
    Content json.RawMessage            // string or array of parts, verbatim
    Extra   map[string]json.RawMessage // name, tool_calls, tool_call_id, future fields
}
func (m Message) Text() string         // concatenated text of a string or text parts; used by mock

type ChatResponse struct {
    Body  json.RawMessage // the complete OpenAI chat.completion object, verbatim
    ID    string          // parsed from Body, for logs
    Model string
    Usage *Usage
}
type ChatChunk struct {
    Data  json.RawMessage // one chat.completion.chunk object, verbatim
    Usage *Usage          // set when the chunk carries usage
}
type Usage struct{ PromptTokens, CompletionTokens, TotalTokens int }
type Model struct {
    ID, OwnedBy string
    Created     int64
}

// Builders for providers that synthesise responses (mock now, native adapters later).
type Completion struct {
    ID, Model, Content, FinishReason string
    Created                          int64
    Usage                            Usage
}
func NewChatResponse(c Completion) (ChatResponse, error)
type Delta struct {
    ID, Model, Role, Content, FinishReason string
    Created                                int64
    Usage                                  *Usage
}
func NewChatChunk(d Delta) (ChatChunk, error)
```

Lossless pass-through: requests are typed only where Spillway must act (`model` to strip the prefix, `messages` for the mock and the v0.3 router).
Everything else, including `tools`, `tool_choice`, `response_format`, `stream_options`, `temperature`, `seed`, `logprobs`, image parts and fields that do not exist yet, rides in `Extra` and is re-emitted as the same JSON values.
`stream` is not stored; `Chat` always sends `"stream": false` and `ChatStream` always sends `"stream": true`, so a client cannot desynchronise the two paths.
Responses and chunks are carried as raw JSON plus a few parsed metadata fields.
Fully typed responses with `Extra` at every nesting level were rejected: they need custom marshalling on six types and still risk dropping nested fields that providers add (OpenRouter `reasoning`, `annotations`), while raw bytes are lossless by construction.
The upstream `model` field in responses is not rewritten (open question 6).

Errors:

```go
var (
    ErrRateLimited         = errors.New("rate limited by provider")
    ErrUnauthorized        = errors.New("provider rejected the provider key")
    ErrUpstreamUnavailable = errors.New("provider unavailable")
    ErrBadRequest          = errors.New("provider rejected the request")
    ErrModelNotFound       = errors.New("model not found")
)

type Error struct {
    Kind       error         // one of the sentinels
    Provider   string
    Status     int           // upstream HTTP status, 0 for transport errors
    RetryAfter time.Duration // 0 when unknown
    Message    string        // upstream message, truncated to 512 bytes, scrubbed
    Err        error         // underlying cause, if any
}
func (e *Error) Error() string
func (e *Error) Unwrap() []error // Kind and Err, so errors.Is works for both
func RetryAfter(err error) (time.Duration, bool)
func ParseRetryAfter(v string, now time.Time) (time.Duration, bool) // seconds or HTTP date
```

Status mapping, shared by all adapters: 429 to `ErrRateLimited` with `Retry-After`; 401 and 403 to `ErrUnauthorized`; 400, 413 and 422 to `ErrBadRequest`; 404 to `ErrModelNotFound`; 5xx, other statuses, transport errors and timeouts to `ErrUpstreamUnavailable`.
`context.Canceled` from the caller is returned unwrapped by the provider so the API layer can tell a client disconnect from an upstream failure.

SSE reader (`NewSSEReader(r io.Reader, maxEvent int)`): line-based on `bufio.Reader`, handles `\n` and `\r\n`, joins multi-line `data:` fields, ignores comment lines (OpenRouter sends `: OPENROUTER PROCESSING`) and `event:`, `id:`, `retry:` fields, and stops at `data: [DONE]`.
Each event is bounded at 1 MiB; a longer event yields `ErrUpstreamUnavailable` ("stream event exceeds 1 MiB") instead of growing memory.
A `data:` payload that is a JSON object with a top-level `error` key yields a `*Error` (mid-stream upstream error).
EOF without `[DONE]` yields `ErrUpstreamUnavailable` ("stream ended without [DONE]") so truncation is never mistaken for success.

### internal/fakenet

A test-support package (imported only from `_test.go` files) providing `Listen() *Listener`, a `net.Listener` whose connections are `net.Pipe` pairs, and `(*Listener).DialContext` for an `http.Transport`.
CODING_STANDARDS.md requires `testing/synctest` for time-dependent code; `httptest.Server` uses real sockets, which are not durably blocking inside a synctest bubble, while `net.Pipe` connections and their deadlines are, so a real `http.Server` and `http.Client` run on the fake clock.
Fixture replay without timing stays on `httptest.Server`, as AGENTS.md requires for adapters.

### internal/providers/openaicompat

```go
type Preset struct {
    Name           string
    DefaultBaseURL string // includes the /v1 path segment
    KeyRequired    bool
    ModelIDPrefix  string // stripped from ids returned by /models ("models/" for Gemini)
}
var (
    Groq       = Preset{Name: "groq", DefaultBaseURL: "https://api.groq.com/openai/v1", KeyRequired: true}
    OpenRouter = Preset{Name: "openrouter", DefaultBaseURL: "https://openrouter.ai/api/v1", KeyRequired: true}
    Ollama     = Preset{Name: "ollama", DefaultBaseURL: "http://localhost:11434/v1"}
)
type Options struct {
    Preset      Preset
    BaseURL     string        // overrides Preset.DefaultBaseURL; for Ollama the config gives the root and /v1 is appended
    APIKey      redact.Secret // the provider key
    Timeout     time.Duration // non-stream total, and stream time to response headers
    IdleTimeout time.Duration // max gap between stream events; default 60s
    HTTPClient  *http.Client
    Scrubber    *redact.Scrubber
    UserAgent   string        // "spillway/<version>"
    Now         func() time.Time
}
func New(o Options) (*Client, error) // validates o; *Client implements providers.Provider
func NewHTTPClient() *http.Client     // the shared client described below
```

Outbound requests are built from an allowlist with `http.NewRequestWithContext`: `Authorization: Bearer <provider key>` only when a provider key is set, `Content-Type: application/json`, `Accept` (`text/event-stream` for streams) and `User-Agent`.
No inbound header is ever copied, so the client app's local key cannot reach a provider.
No OpenRouter attribution headers are sent by default.
`Models` calls `GET {base}/models` and returns the provider's own list; nothing is hardcoded.
`Chat` posts with `context.WithTimeout(ctx, Timeout)` and caps the response body at 32 MiB.
`ChatStream` sends the request, waits for response headers within `Timeout`, and returns a `*providers.Error` synchronously on a non-2xx status, so the API layer can still answer with a proper HTTP status before any SSE bytes are written.
The stream's idle timeout is a `time.AfterFunc` that cancels the per-request context and is reset on every event; expiry surfaces as `ErrUpstreamUnavailable` ("no stream data for 60s").
Error bodies are read up to 64 KiB, the OpenAI `error.message` is extracted when present, truncated to 512 bytes and scrubbed.
`defer resp.Body.Close()` on every non-stream path; the stream's `Close` closes the body.

Shared HTTP client: `http.Client{Timeout: 0}` (a client timeout would kill long streams; per-request contexts bound each call), `CheckRedirect` returning `http.ErrUseLastResponse` (a POST must not follow redirects, and no credential may follow one), and a cloned default transport with dial timeout 10s, `TLSHandshakeTimeout` 10s, `Proxy: http.ProxyFromEnvironment`, and TLS verification left on.

### internal/providers/gemini

Gemini is reached through its OpenAI-compatible endpoint `https://generativelanguage.googleapis.com/v1beta/openai` (open question 5, recorded in ADR 0001).
`gemini.New` wraps an `openaicompat.Client` with the preset `{Name: "gemini", KeyRequired: true, ModelIDPrefix: "models/"}` and adds Gemini-specific error parsing: this endpoint can return the error as a one-element JSON array `[{"error": {...}}]` and uses status `RESOURCE_EXHAUSTED` with 429.

### internal/api

```go
// LocalKey is one local key and the name of the client app that presents it.
type LocalKey struct {
    Name string
    Key  redact.Secret
}

type Options struct {
    Providers         providerSet      // interface defined in api: Lookup, All
    LocalKeys         []LocalKey       // at least one; NewHandler rejects an empty list or a zero key
    AllowedHosts      []string         // non-nil enables the Host check; internal/cli sets it only for loopback listens
    Logger            *slog.Logger
    Scrubber          *redact.Scrubber
    MaxBodyBytes      int64            // default 10 MiB
    BodyReadTimeout   time.Duration    // default 30s
    ChunkWriteTimeout time.Duration    // default 30s, per write to the client
    ModelsTimeout     time.Duration    // per provider, default 10s
}
func NewHandler(o Options) (http.Handler, error)
func NewServer(addr string, h http.Handler, logger *slog.Logger) *http.Server
func LoopbackHosts(listenHost string) []string // "localhost", "127.0.0.1", "::1" and listenHost, deduplicated, lowercased
```

Routing uses `http.ServeMux` method patterns: `POST /v1/chat/completions`, `GET /v1/models`, `GET /healthz`.
A catch-all handler returns an OpenAI-shaped 404 for unknown paths and 405 (with `Allow`) for wrong methods, because the stock mux writes plain-text errors.

Middleware order, outermost first: recover (panic logged scrubbed, client gets an OpenAI 500), then access log, then the `Host` check (every path, `/healthz` included), then auth (every path except `/healthz`), then the mux.
The `Host` check runs before auth so a rebound request is refused without ever reaching the key comparison or a provider, and after the access log so refusals are still logged.
Access log keys: `method`, `path`, `status`, `client_app`, `provider`, `model`, `stream`, `latency_ms`, `bytes`; never bodies, never headers, never a key.
Because the access log wraps auth, it puts a mutable per-request record into the context first; auth fills in `client_app` and the chat handler fills in `provider` and `model`, and the log line is written from that record when the inner handler returns.
`client_app` is omitted for `/healthz` and for requests refused by the `Host` check or auth.

`Host` check (ADR 0003): when `AllowedHosts` is non-nil, the request's `r.Host` is reduced to its host part (port stripped with `net.SplitHostPort` when present, brackets stripped from a bare IPv6 literal) and compared case-insensitively against the list.
`internal/cli` passes `api.LoopbackHosts(listenHost)` when `config.Server.Loopback()` is true and `nil` otherwise, so the check never applies on a non-loopback listen.
The port is not compared: a DNS rebinding page controls the name in `Host`, not the port, and a `listen` port of 0 is only known after binding.
An empty `Host`, a trailing-dot name (`localhost.`), a suffix match (`localhost.evil.example`) and any name not in the list are refused; there is no wildcard or suffix matching.
Refusal is `403` with `{"error":{"message":"Host header not allowed. Spillway listens on loopback and accepts only localhost, 127.0.0.1, [::1] or its listen address; use one of these in the base URL.","type":"invalid_request_error","param":null,"code":"host_not_allowed"}}`.
The message never echoes the presented `Host`, so the response reflects no attacker-chosen text.
403 was chosen over 421 Misdirected Request: 421 means "retry on another connection", and browsers and HTTP/2 clients retry it automatically, while the OpenAI SDKs map 403 to `PermissionDeniedError` and never retry it.
400 was rejected because the request is well formed; the refusal is policy, not syntax.

`/healthz` is unauthenticated, is still subject to the `Host` check, and returns `200` with `Content-Type: text/plain; charset=utf-8` and the body `ok`, nothing else: no version, provider names or configuration.

Auth: every request except `/healthz` needs `Authorization: Bearer <local key>` (scheme case-insensitive); there is no unauthenticated mode, and `NewHandler` returns an error when `LocalKeys` is empty or holds a zero key, as defence in depth behind config validation.
The presented token and each local key are hashed with SHA-256 at construction (keys) or per request (token), and the digests are compared with `crypto/subtle.ConstantTimeCompare` against every local key, with no early exit.
The matching index is accumulated with `subtle.ConstantTimeSelect` (`idx = ConstantTimeSelect(eq, i, idx); matched |= eq`), so neither the key length nor which key matched leaks through timing; the name is looked up only after the loop.
Config guarantees key values are unique, so at most one key matches.
On success the client app name is stored in the request context (unexported key, read by the access log and, from v0.4, by usage logging) and logged as `client_app=<name>`; the key itself is never stored in the context or logged.
Failure is 401 `{"error":{"message":"Invalid API key. Provide a valid key in the Authorization header as \"Bearer <key>\".","type":"authentication_error","param":null,"code":"invalid_api_key"}}`, the OpenAI wording that SDKs expect; the presented value is never echoed or logged.

Chat flow:
1. Set the body read deadline with `http.ResponseController.SetReadDeadline(now+BodyReadTimeout)`, read through `http.MaxBytesReader(MaxBodyBytes)`, then clear the deadline.
2. Decode into `ChatRequest`; require a string `model` and a non-empty `messages` array, else 400.
3. Resolve the model reference with `providers.ParseModelRef` and `Lookup`.
   The virtual models `auto` and `spillway/<tier>` return 404 `model_not_found` with "model \"auto\" needs the router, which arrives in v0.3; use provider/model, see GET /v1/models" (open question 6).
   A model reference with no `/` or an unconfigured provider returns 404 `model_not_found` naming the configured providers.
4. Set `x-spillway-provider` and `x-spillway-model` (the upstream model) before calling the provider, so they are present on success and on upstream errors.
5. Read `stream` from `Extra` (then drop it).
   Non-stream: `Chat`, then write `Body` with `Content-Type: application/json`.
   Stream: `ChatStream`; an error becomes a normal JSON error response.
   On success: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`; for each chunk, `SetWriteDeadline(now+ChunkWriteTimeout)`, write `data: <Data>\n\n`, and flush via `http.ResponseController`; at `io.EOF`, write `data: [DONE]\n\n`.
   A mid-stream error writes `data: {"error":{...}}\n\n` and ends without `[DONE]`; the OpenAI SDKs raise an `APIError` on such an event, and the missing `[DONE]` keeps the truncation visible.
   `defer stream.Close()` always runs.
6. Client disconnect cancels `r.Context()`, which is the context passed to the provider, so the upstream request is cancelled; a write error or an expired write deadline also stops the loop and closes the stream.

Error mapping to the OpenAI shape `{"error":{"message","type","param","code"}}`:

| Cause | Status | type | code |
|---|---|---|---|
| `Host` not allowed (loopback listen) | 403 | invalid_request_error | host_not_allowed |
| missing or wrong local key | 401 | authentication_error | invalid_api_key |
| bad JSON, missing fields | 400 | invalid_request_error | invalid_request |
| body over limit | 413 | invalid_request_error | request_too_large |
| model resolution, `ErrModelNotFound` | 404 | invalid_request_error | model_not_found |
| `ErrBadRequest` | 400 | invalid_request_error | upstream_bad_request |
| `ErrRateLimited` | 429 + `Retry-After` (seconds, rounded up) | rate_limit_error | rate_limit_exceeded |
| `ErrUnauthorized` (provider key) | 502 | api_error | upstream_unauthorized |
| `ErrUpstreamUnavailable`, timeouts | 502 | api_error | upstream_unavailable |
| panic, unknown error | 500 | api_error | internal_error |

A bad provider key is a 502, not a 401, because a 401 would tell OpenAI SDKs that the client app's local key is wrong.
Every message passes through `Scrubber.Scrub` before it is written.
Each upstream error is logged once by the access log line (`error` key, scrubbed) and returned once to the client, following "handle each error once".

`GET /v1/models` calls every provider's `Models` concurrently (one goroutine per provider, owned by the handler and bounded by `ModelsTimeout` and the request context), prefixes each upstream model as a model reference `provider/model`, sorts by id, and returns `{"object":"list","data":[{"id","object":"model","created","owned_by"}]}`.
A provider that fails is omitted and logged (scrubbed) at warn level, so one unreachable Ollama does not hide the others; if every provider fails the response is 502 (open question 7).
Virtual models (`auto`, `spillway/<tier>`) are not listed until v0.3.

Server timeouts (`NewServer`): `ReadHeaderTimeout` 10s, `ReadTimeout` 0, `WriteTimeout` 0, `IdleTimeout` 120s, `MaxHeaderBytes` 64 KiB, and `ErrorLog` bridged to the scrubbing slog handler with `slog.NewLogLogger`.
`ReadTimeout` stays 0 on purpose: net/http keeps the connection read deadline during the handler, and when it expires the background read cancels the request context, which would kill any stream longer than the timeout.
The body is instead bounded by the per-request read deadline in step 1, and slow clients during streaming by the per-write deadline in step 5.

## Hard-rule check

- No quota evasion: config holds one provider key per provider (`api_key` is a scalar, not a list), there is no rotation, and v0.1 has no spillover at all; local keys name client apps and never select a provider account.
- No credential collection: the only secrets are the local user's provider keys and their own local keys, read from env vars (or a fake literal in the mock example) at startup and held in memory as `redact.Secret`; nothing is written to disk.
- Secrets never leak: `redact.Secret` redacts under fmt, JSON, YAML and slog; local keys are `redact.Secret` and are identified in logs only by name (`client_app=<name>`); `Scrubber` cleans upstream error text and every outgoing error message; the logger is wrapped by the scrubbing handler; outbound requests are built from an allowlist, so the inbound `Authorization` header is never forwarded; tests in T2, T3, T4, T6, T7, T9, T10, T11 and T12 assert key absence in each channel.
- Single binary, no cgo: `make build` and `make lint` run with `CGO_ENABLED=0`, and `lint` builds `./...` that way on every `make check`; the only new runtime dependency (`go.yaml.in/yaml/v3`) is pure Go; the race detector's cgo use is test-only.
- Local by default: `server.listen` defaults to `127.0.0.1:8080`; validation refuses any config without a local key, loopback included (ADR 0003, stricter than the rule's non-loopback requirement); on loopback the `Host` check refuses rebound requests before auth; outbound calls go only to configured provider base URLs; redirects are not followed; no telemetry.
- OpenAI compatibility: request fields pass through losslessly, responses and chunks are relayed verbatim, errors (including the 403 `Host` refusal and the 401) use the OpenAI error object, SSE ends with `data: [DONE]`, and the manual verification exercises the official OpenAI Python SDK.

## Decisions

Resolved 2026-10-14: every open question below was accepted with its recommended default. Questions 1 and 5 are recorded as ADRs.

1. **Where the `tool` directives live.** Both pinned tools (golangci-lint v2.13.2, govulncheck v1.8.0) declare `go 1.26.0`, so putting `tool` lines in the root `go.mod` raises the root directive to `go 1.26.0` and adds about 226 golangci-lint requirements to the binary's module graph. Options: (a) root `go.mod`, sharing the module graph; (b) a separate `tools/go.mod` with the `tool` directives, run with `go tool -modfile=tools/go.mod` (verified working here), keeping the binary's graph clean. **Decided: (b), ADR 0002.**
2. **Unset or empty env vars.** Options: error, empty string, or keep the literal `${X}`. **Decided:** error naming the variable and YAML path, never a value, for both unset and empty, so a missing provider key is caught by `spillway check` rather than as an upstream 401.
3. **Unknown config fields.** Options: strict (error) or lenient (warn). **Decided:** strict, with friendly milestone messages for `tiers`, `router`, `budgets` and `cache`.
4. **`examples/config.mock.yaml` local key.** Options: a literal fake key `sk-test-spillway-mock` in the file, or `${SPILLWAY_KEY}` with the Makefile supplying a value. **Decided:** the literal fake local key (named `demo`), clearly commented, because `make mock` must run with no environment setup and ADR 0003 requires a local key even on loopback.
5. **Gemini API.** Options: the OpenAI-compatible endpoint (`/v1beta/openai`) or native `generateContent` with a translation layer. **Decided:** the compatibility endpoint for v0.1 (Bearer auth, verbatim pass-through, model listing), revisiting native only if a needed feature is missing; **Decided, ADR 0001.**
6. **Model selection in v0.1.** For the virtual models `auto` and `spillway/<tier>`: (a) return an OpenAI-shaped 404 `model_not_found` pointing at v0.3 and model references (`provider/model`); (b) parse `tiers` now and use the tier's first model with no spillover. Related: rewrite the response `model` field to the model reference, or keep the upstream value. **Decided:** (a), reject `tiers` in config until v0.2, and keep the upstream `model` value (the `x-spillway-model` header carries the upstream model Spillway chose); (b) would ship tier semantics that change in v0.2 and v0.3.
7. **`/v1/models` failure policy and `/v1/embeddings`.** Options: fail the whole request if any provider fails, or return partial results. **Decided:** partial results with a warn log, and 502 only when every provider fails. `/v1/embeddings` stays out of v0.1 because the milestone text does not include it; schedule it with v0.2.
8. **Request body limit.** Options: a fixed 10 MiB, or a `server.max_body_bytes` setting. **Decided:** fixed 10 MiB in v0.1 (enough for several base64 images), made configurable only when a user hits it.

### Grilling outcomes (2026-10-14)

These amend the approved plan after a grilling session; `GLOSSARY.md` and ADR 0003 were written in the same session.

1. **Local key always required (ADR 0003).** `server.api_keys` must list at least one local key on every listen address, loopback included, and `serve` and `check` refuse a config without one. The earlier "optional on loopback" rule is removed, along with the unauthenticated mode in `api`. Reason: loopback is not a trust boundary against the browser (simple cross-origin POSTs and DNS rebinding).
2. **Loopback `Host` check (ADR 0003).** On a loopback listen, every request (including `/healthz`) whose `Host` is not `localhost`, `127.0.0.1`, `[::1]` or the listen host, with or without a port, is refused before auth with an OpenAI-shaped 403 `host_not_allowed`. 403 was chosen over 421 (auto-retried by browsers and HTTP/2 clients) and 400 (the request is well formed). The check is off on non-loopback listens, where the local key is the boundary.
3. **`/healthz`.** Unauthenticated, still subject to the `Host` check, and returns only `ok` as `text/plain`.
4. **Named local keys.** `server.api_keys` entries are a plain string (named `key-1`, `key-2`, ... by list position) or `{name, key}`. Names are unique, `[a-z0-9-]{1,64}`; key values are unique and held as `redact.Secret`. Auth compares against every local key in constant time and selects the match without branching, stores the client app name in the request context, and logs `client_app=<name>`, never the key.
5. **Terminology.** The plan uses `GLOSSARY.md` terms: local key, provider key, model reference, upstream model, virtual model, tier (user-named `[a-z0-9-]`, still rejected in v0.1 config until v0.2), spillover, client app.
