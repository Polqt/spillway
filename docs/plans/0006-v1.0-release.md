## Goal

Spillway v1.0 is the first public, reproducibly built, open-source release.
A developer can download a checksummed binary or Docker image, run `spillway init`, start `spillway serve` and get a working OpenAI-compatible answer in under five minutes, with no mandatory cloud service, database or Ollama.
Every claim in the docs is either covered by an offline test, recorded as a dated manual check, or listed as unverified.

## 1. Critical assessment of the current codebase

Assessed on 2026-10-16 at commit `223ded6` by reading the code, ADRs, plans and tests, and by running the tools.

### Verified working

| Area | Evidence |
|---|---|
| Lint, build without cgo, tests with `-race` | `make check` green on Windows amd64, Go 1.27.2: golangci-lint 0 issues, 18 test packages pass with `-race`, 72 s wall time. |
| Known vulnerabilities | `make vuln`: "No vulnerabilities found." |
| Local auth | `internal/api/auth.go`: SHA-256 digests, constant-time compare and select, mandatory key (ADR 0003). |
| Loopback Host check | `internal/api/host.go`, applied only on loopback listeners. |
| Dashboard authorization | `/api/*` requires a `dashboard: true` key; CSP and no-inline-script rules (ADR 0012), tested in `tests/api/dashboard_test.go` and `tests/web/`. |
| Streaming robustness | `tests/api/stream_test.go` covers partial reads, client disconnect cancelling the provider, mid-stream upstream errors, stalled clients, idle timeouts and per-chunk flushing. |
| Outbound timeouts and bounds | `openaicompat` uses per-request deadlines, a stream idle timer, no redirects and bounded bodies; classifier has a 3 s client timeout. |
| Config strictness | Unknown and duplicate fields rejected; secrets scrubbed from config errors. |

### Release blockers

1. **No license.** The repository has no `LICENSE`, so it cannot be used as open source.
2. **No distribution pipeline.** There is no `.goreleaser.yaml`, no Dockerfile, no `.github/` directory, no CI and no git tag.
3. **Linux and macOS are unverified.** Every recorded test run is on Windows; AGENTS.md requires Linux and macOS to work.
4. **`spillway init` does not exist.** CONTEXT section 11 promises it for v1.0; the five-minute path today needs a hand-written config and three to four exported variables.
5. **ADRs 0009 to 0013 are untracked.** Committed code, README and CONTEXT cite them, but `git ls-files docs/adr` lists only 0001 to 0008 and 0014.
6. **`logging.level` is validated but ignored.** `internal/cli/serve.go` builds `slog.NewTextHandler(stderr, nil)`, so `warn`, `error` and `debug` have no effect.
7. **Docs claim unimplemented features.** CONTEXT lists `POST /v1/embeddings` (no route exists; the catch-all returns 404) and adapters for Mistral, Anthropic and OpenAI (only gemini, groq, mock, ollama and openrouter exist); CODING_STANDARDS mentions `logging.bodies`, which config rejects. README has no install, quickstart for real providers, or troubleshooting.

### High-priority reliability and security gaps

8. **Graceful shutdown is untested and can lose the last usage record.** `serveUntilDone` cancels requests when the 10 s grace expires and returns without waiting for handlers, then the deferred `store.Close` runs while a handler may still be recording. No test in `tests/` exercises shutdown.
9. **A second Ctrl-C is swallowed.** `signal.NotifyContext` stays registered until `Run` returns, so the user waits out the grace period.
10. **Race detection depends on the dev machine.** The Makefile silently drops `-race` when cgo is unavailable, and there is no CI to catch that.
11. **Docker and Ollama do not combine.** `base_url` must be https unless loopback, so `http://host.docker.internal:11434` or `http://ollama:11434` is refused, and the classifier requires a loopback Ollama (ADR 0014).
12. **Version output is thin.** `spillway version` prints only the `-X` version; `go install ...@v1.0.0` reports `dev`, and no commit or build date is shown.

### Medium and hygiene

13. **Routing evaluation has no model-backed evidence.** The v0.5 runs used `mock/echo`, six prompts and no ratings; the bootstrap intervals came from an uncommitted `.scratch/.../bootstrap.go` and a Python snippet in the docs.
14. **Provider presets are scattered.** Default base URLs and key rules live in `internal/cli/serve.go`, `internal/catalog/catalog.go` and `internal/config/validate.go`; `init` would make a fourth copy.
15. **Repository root holds runtime files.** `spillway-mock.db*` and `spillway-paid-manual.db*` are untracked and not ignored.
16. **Missing environment variables are reported one at a time.** `expandValue` fails on the first unset variable.

## Design

### Compatibility promise (new ADR 0015)

v1.0 starts semantic versioning and names its stable surface:
config schema, CLI subcommands `serve`, `check`, `init`, `version`, `catalog` and their flags, exit codes 0/1/2, `/v1/*` shapes, `/healthz`, `/api/*` response fields, `x-spillway-*` header names and the route grammar (ADRs 0008 and 0014), and the store schema.
`eval`, `eval-score` and `eval-report` are marked experimental and outside the promise.
Every v0.1 to v0.5 example config must load unchanged; this is locked by fixtures copied from each milestone's final commit.
v1.0 makes **no store schema change**, so a v1.0 database still opens with a v0.5 binary and rollback needs no migration.
New config fields are additive; an older binary rejects a config that uses them, which the upgrade notes state.

### Provider preset table (prefactor)

One table in `internal/providers` replaces the three scattered copies:

```go
// Preset describes a built-in provider: how to reach it and what config it accepts.
type Preset struct {
	Name               string // "groq"
	DefaultBaseURL     string // "https://api.groq.com/openai/v1"; "" for mock
	KeyEnv             string // "GROQ_API_KEY"; "" when no key is accepted
	RequiresKey        bool
	FreeTierAttestable bool   // ADR 0005: groq and gemini only
	SuggestedModel     string // init's offered default, labelled as a suggestion
}

func Presets() []Preset
func LookupPreset(name string) (Preset, bool)
```

`config` validation, `cli` wiring, `catalog` and `init` all read it.
Behaviour is unchanged; existing tests prove it.
Rejected: a per-provider package registry, because only Gemini differs in code and it already has its own package.

### `spillway init` (new ADR 0017)

`Run` gains an `io.Reader` for stdin: `Run(ctx, args, stdin, stdout, stderr, lookupEnv)`.
`init` prompts on stdin with plain `bufio` line prompts; no TUI dependency.
Flags make every prompt answerable non-interactively: `-config`, `-providers`, `-attest-free-tier`, `-store`, `-yes`.
With `-yes`, an unanswered required choice is an error that names the flag, never a silent default.

Rules:
- Provider keys are never asked for, read, echoed or written; the config gets `${GROQ_API_KEY}`-style references from the preset table, and init reports per variable only `set` or `not set`.
- The local key is generated with `crypto/rand` (32 bytes, base64url, `sk-spillway-` prefix) and written as a literal into the new config file (decision D3). It is never printed; next steps tell the user where it is.
- The file is created with `O_CREATE|O_EXCL` and mode 0600; an existing file is never overwritten.
- Free-tier attestation for Groq and Gemini is an explicit yes/no question defaulting to no; an unattested provider is configured but kept out of the zero-spend tier, and init says why (ADR 0005).
- Init builds one `free` tier from one suggested model per eligible provider, sets `router.auto: [free]`, and optionally adds `store:` with a `dashboard: true` key. It never writes paid tiers, budgets, rules or the classifier.
- Before writing, init validates its output with `config.ParseWithEnv` using a lookup that supplies placeholders, so it cannot write an invalid config.
- A "mock (offline, no keys)" choice gives a zero-network quickstart.

### Config DX

`expandConfig` collects every missing variable and reports them in one error, names only.
A missing default `config.yaml` error suggests `spillway init`.

### Logging level

`serve` passes `&slog.HandlerOptions{Level: level}` built from `cfg.Logging.Level` into the text handler under the redacting handler.

### Shutdown

- `serveUntilDone` tracks in-flight handlers with a `sync.WaitGroup` middleware, calls `Shutdown` with the grace timeout, cancels remaining requests, then waits for handlers to return (bounded by a further fixed 5 s) before returning, so `store.Close` runs last.
- New optional `server.shutdown_timeout` (default 10s, 1s to 5m) makes the grace configurable for orchestrators; Docker docs pair it with `docker stop --time`.
- `main` calls `stop()` as soon as the first signal arrives, so a second Ctrl-C terminates immediately with the default handler.
- Exit code stays 0 for a clean drain and 1 when requests had to be cancelled, with a message saying how many.

### Version metadata

`version` keeps the `-X` override and fills gaps from `runtime/debug.ReadBuildInfo`: `Main.Version` when `-X` is `dev` (so `go install @v1.0.0` reports `v1.0.0`), plus `vcs.revision`, `vcs.time` and `vcs.modified`.
Output: `spillway v1.0.0 commit 1a2b3c4 built 2026-11-01T10:00:00Z go1.27.2 linux/amd64`.
`--version`, `-version`, `help`, `-h` and `--help` are accepted aliases.
Rejected: extra `-X` ldflags for commit and date, because build info already carries them and stays correct for `go install`.

### Distribution (new ADR 0016)

- GoReleaser v2.18.2 (released 2026-09-17), pinned as a `tool` in `tools/release/go.mod` per ADR 0018 and run through `make snapshot` and `make release-check`.
- Builds: `CGO_ENABLED=0`, `-trimpath`, `-ldflags "-s -w -X .../cli.version={{.Version}}"`, `mod_timestamp: "{{ .CommitTimestamp }}"`, linux, darwin and windows on amd64 and arm64.
- Archives: `tar.gz` (zip on Windows) containing the binary, `LICENSE`, `README.md` and `examples/config.mock.yaml`; `checksums.txt` with sha256.
- Release notes generated from Conventional Commits; no hand-edited CHANGELOG.md.
- Image: `apps/spillway/Dockerfile` on `gcr.io/distroless/static-debian12:nonroot` pinned by a digest at least two weeks old, user 65532, `ENTRYPOINT ["/spillway"]`, `CMD ["serve","-config","/etc/spillway/config.yaml"]`, `EXPOSE 8080`, store directory `/var/lib/spillway`. Built for linux/amd64 and linux/arm64 by GoReleaser and pushed to `ghcr.io/polqt/spillway`.
- In a container Spillway must listen on `0.0.0.0:8080`, which turns the loopback Host check off; docs require publishing with `-p 127.0.0.1:8080:8080` and rely on the mandatory local key (ADR 0003). `examples/config.docker.yaml` encodes this.
- Provenance: GitHub artifact attestations for archives and the image (decision D6).
- The release toolchain is one exact Go patch version pinned in the workflow and recorded in each release's notes; CI also tests the oldest supported Go (`go` directive, 1.26).

### CI

- `.github/workflows/ci.yml` on pull requests and pushes to `main`, `permissions: contents: read`, actions pinned to commit SHAs:
  - `check`: ubuntu, macos, windows, each on Go 1.26.x and the pinned release version, running `make check` with `RACE=-race` forced so a missing C compiler fails loudly.
  - `vuln`: `make vuln`.
  - `release-dry-run`: `make release-check`, `make snapshot` twice, compare binary sha256 sums for reproducibility, then build the image, run it with the Docker example config and send one chat request.
- `.github/workflows/vuln-weekly.yml`: scheduled `make vuln` and a short fuzz run.
- `.github/dependabot.yml`: `gomod` for `/` and `/tools`, `github-actions`, weekly.
- `.github/workflows/release.yml` on `v*` tags: `make check`, GoReleaser release, image push, attestations; `permissions` limited to `contents: write`, `packages: write`, `id-token: write`, `attestations: write`.

### Egress guard

A test walks `internal/` and `apps/` and fails when a non-test Go file contains an `http://` or `https://` literal outside an allowlist (the three provider defaults and loopback Ollama).
`docs/security.md` lists every outbound destination, when it is contacted, and that the transport honours `HTTP(S)_PROXY`.

### Evaluation (ADR 0014 protocol unchanged)

- `examples/evaluation-prompts.v2.json`: representative, authored prompts with no personal data, stratified by authored difficulty and covering plain chat, coding, extraction, reasoning, long input, tool definitions and JSON mode, so every rule condition is exercised. Size per decision D9.
- `spillway eval-report -run dir -scores a.csv,b.csv -baseline current-auto -seed N -replicates 10000` replaces the scratch bootstrap file and the Python snippet: it reads `metrics.json`, the blind key and several rater sheets, averages raters per answer, reports inter-rater agreement and every ADR 0014 gate with its paired prompt-cluster bootstrap interval, by difficulty and in aggregate, and prints PASS, FAIL or INCONCLUSIVE per gate.
- Score sheets gain a `rater_id` column; v0.5 single-rater sheets still load.
- One live run (decision D9) of current auto, rules and the Ollama classifier with real priced candidates, Spillway budgets as the spend cap, and blinded independent ratings. Results go in `docs/v1.0-routing-evaluation.md` and an outcome section appended to ADR 0014.
- Whatever the result, v1.0 runtime defaults do not change (ADR 0015); a passing stage changes only documentation recommendations.

## Hard-rule check

- **No quota evasion:** no routing or key-handling change; init writes one key reference per provider.
- **No credential collection:** init never reads provider keys; it generates only the user's own local key.
- **Secrets never leak:** tests assert generated local keys and env values are absent from init, check, version, logs and binary-test output; release audit covers new code.
- **Single binary, no cgo:** GoReleaser and every CI build use `CGO_ENABLED=0`; GoReleaser lives in `tools/release/go.mod`, outside the binary's module graph.
- **Local by default:** default listen unchanged; init writes `127.0.0.1:8080`; the Docker example publishes only to host loopback and keeps keys mandatory; the egress test blocks new outbound hosts.
- **OpenAI compatibility:** no change to `/v1/*`; binary tests replay the README quickstart through real HTTP.

## Rollback strategy

- Tags are never deleted or moved: the Go module proxy caches `v1.0.0` permanently.
- A broken release is fixed forward with `v1.0.1`; if it is unsafe to use, `go.mod` gains `retract v1.0.0` with the reason, and the GitHub release is edited to point at the fix.
- Floating image tags (`1`, `1.0`) are repointed to the last good digest with `docker buildx imagetools create`; immutable version tags stay.
- Users roll back by installing the previous version; v1.0 changes no store schema, so a v1.0 database opens with v0.5, and a config that avoids v1.0-only fields loads on v0.5.
- A GoReleaser build failure occurs before publication, but later workflow failures can leave a GitHub release, versioned image, or stable image aliases published without all provenance attestations.
  Treat artifacts from a failed workflow as unverified, keep the tag immutable, and publish a corrected `rc.N` or patch release rather than moving or deleting the tag.
  For a failed stable release, update the GitHub release to point users to the fixed-forward version and repoint floating image aliases to the last good digest.
