# v1.1.0 CLI Management

Status: approved (revised 2026-10-20; all open questions resolved)
Milestone: v1.1.0 core (C1 to C7); deferred work targets CLI management phase 2 (v1.2 or a later minor) and a separate self-upgrade milestone with no target yet

## Goal

A developer can add a supported provider to an existing config, see which providers and keys the config holds, and diagnose configuration, environment-variable and port problems from `spillway` commands instead of hand-editing YAML or reading the README.
`provider add` validates, previews, backs up and atomically replaces the config, and never writes a provider key value.
Everything else from the first draft (key lifecycle, provider removal, model and tier commands, gateway status, provider tests and self-upgrade) keeps its design here but is deferred and not approved for implementation.

This plan authorizes the core tickets C1 to C7 for ticketing.
It authorizes no ticket creation by itself, no edit to plan 0009, no ADR file outside the tickets named, no tag and no publication.

## Approved decisions (owner, 2026-10-20)

Hard rules:

1. The outbound-network restriction stays as written.
   v1.1.0 has no networked self-upgrade, and `spillway upgrade --check` is deferred because it needs an outbound call the rule does not allow.
2. A local key may be displayed once, only during explicit creation or rotation, after confirmation.
   Existing key values are never exposed through `show`, `list`, logs, config printouts or dashboard responses.
3. Multiple Groq accounts for quota rotation stay refused; users upgrade their provider plan or configure another supported provider.

Planning:

1. Release placement: a core subset ships in v1.1.0; advanced commands move to v1.2 or later, or a dedicated maintenance milestone; v1.1.0 is not delayed for the full first-draft ticket set.
2. Key display: only at creation or rotation, never for existing keys, with a clear warning to save the credential securely (deferred with the key commands).
3. Stability: new config-mutating commands are experimental for one release; existing stable commands stay stable.
4. Networked upgrade: deferred; offline, installation-method-aware upgrade guidance ships instead.
5. Release signing: Ed25519-signed checksums are approved as a future prerequisite for trusted self-upgrade.
   Key management, trusted public-key distribution, rotation and compromise recovery must be documented before implementation.
   Existing checksums alone are insufficient.

Additional requirements:

- Preserve the v1.0 compatibility promise and existing command behavior.
- Use atomic config updates, validation, restrictive file permissions and safe backups.
- Handle Windows executable replacement separately, with no unsafe in-place replacement.
- Do not expose local key prefixes unless their security implications are documented and approved.
- Keep shell guidance informational and offline.
- Provider removal must display affected model references, tiers and routing configuration, require confirmation, and reject changes that leave an invalid config.
- Do not introduce a new identity header unless necessary; preserve existing local-key identification semantics.

v1.1.0 priority: CLI help and onboarding, a safe `spillway doctor`, `spillway provider add|list|show` on the existing presets, clear recovery guidance and next steps, and polish of the existing CLI and dashboard integration.

## Scope

In (v1.1.0 core):

- `spillway provider list` and `spillway provider show <name>`: read-only, offline, stable.
- `spillway provider add`: experimental for v1.1.x; adds one preset provider to an existing config, optionally placing its suggested model in a zero-spend tier.
- The config edit engine and atomic commit that `provider add` needs (ADR 0025).
- `spillway doctor`: read-only, stable; config, environment variables with offline shell guidance, provider key mistakes, local key entries by name and location, the listen address, the store schema, the install channel with offline upgrade guidance, and `PATH` shadowing (ADR 0026).
- A `providers` field in the `serve` startup summary from 0009 T05, so the running server's loaded providers are visible.
- Help groups and next-step hints that point to `doctor` and `provider add`; `init`'s existing-config hint names `provider add`.
- Docs, glossary, troubleshooting and cross-OS tests for the above.

Out (deferred, designs kept below, not approved for implementation):

- Key commands (`key list`, `key create`, `key rotate`, `key revoke`): CLI management phase 2.
- `provider remove`: phase 2.
- `model list`, `tier list`, `tier show`: phase 2.
- Model, tier and pricing editing, `provider set`, `config restore`: phase 2 or later.
- `spillway status` (comparing a running server with a config needs a local key sent to the listener, which needs a verification design): phase 2.
- `provider test`, both the zero-spend model listing and the spending one-token chat: phase 2.
- `spillway upgrade`, `upgrade --check`, release signing and executable replacement: self-upgrade milestone, blocked on a hard-rule amendment that is not planned and on the signing prerequisites.

Out (non-goals, unchanged from the first draft):

- A second instance of the same provider in any form, key pooling or account rotation.
  The schema keys `providers` by preset name and rejects duplicates, so no multi-instance case exists; a future case that differs by service (two Ollama hosts, a self-hosted OpenAI-compatible endpoint) needs a schema ADR and is not planned.
- Prompting for, reading into config, storing or printing provider key values (ADR 0017 unchanged).
- Revealing an existing local key by any command; showing local key prefixes, fingerprints or hashes.
- A new identity header on `/healthz` or any other endpoint.
- Machine-readable `--json` output, clipboard copy, remote inspection over a network.
- `/v1/responses` (OpenAI Responses API) and embeddings; clients that require them, such as Codex CLI 0.163.0 with `wire_api = "responses"`, are a known limitation.
- Hot reload of config by a running server.
- Encrypted at-rest key storage.
- Telemetry or any background network call.
- Any change to `init`, `check`, `serve`, `catalog`, `version` or `eval*` flags, exit codes or config behavior.

### Current architecture assessment

CLI:

- `cli.Run(ctx, args, stdin, stdout, stderr, lookupEnv)` is the tested entry point and `apps/spillway/main.go` only calls it.
- Cobra (ADR 0020) wraps legacy commands that re-parse original arguments with the standard `flag` package, so `-config` keeps working; `normalizeLegacyFlags` rewrites single-dash flags found by `command.Flags().Lookup`.
- Exit codes are 0, 1 and 2 (`normalizeExitCode`).
- `init` uses Huh accessible mode and a line-prompt path for flags and `-yes`.
- Nothing detects whether stdin or stdout is a terminal.

Configuration:

- `config.LoadWithEnv` reads at most 1 MiB, rejects unknown fields on the node tree, expands `${VAR}` in listed fields, decodes with `KnownFields(true)`, applies defaults and validates.
- Provider names must be presets; provider `api_key` must be exactly a `${VAR}` reference; `free_tier` is accepted only on `groq` and `gemini` (ADR 0005).
- Local keys may be literals or `${VAR}` references, must be unique and at least one is required (ADR 0003).
- A parsed `Config` holds expanded secrets and marshals them as `[REDACTED]`, so writing a file from a `Config` would corrupt keys or, with `Reveal()`, write provider keys; mutation never marshals a `Config`.

Provider presets (`internal/providers/presets.go`) give name, default base URL, key variable, key requirements, attestation support and a suggested model; they drive `init`, `provider add` and `provider list`.

Gateway behavior that `doctor` relies on, all existing and unauthenticated:

- `GET /healthz`: 200, `Content-Type: text/plain; charset=utf-8`, body `ok`.
- Any authenticated path without `Authorization`, for example `GET /v1/models`: 401, `application/json`, OpenAI error shape with `type` `authentication_error` and `code` `invalid_api_key`; `type` and `code` are stable under ADR 0015.
- On a loopback listener, a request whose `Host` is not allowed: 403 with `code` `host_not_allowed`, checked before authentication (ADR 0003).

Release infrastructure: GoReleaser v2.18.2 builds six archives with `-tags dashboardassets` and an unsigned sha256 `checksums.txt`; GitHub provenance attestations cover archives and the image; no package-manager channel exists (ADR 0016); `tests/e2e/egress_test.go` allowlists every production URL literal.

Compatibility promise (ADR 0015): `serve`, `check`, `init`, `version`, `catalog`, their flags and exit codes, the config schema, `/v1/*`, `/healthz`, `/api/*` field meanings and the `x-spillway-*` header names are stable; `eval*` is experimental; minor releases may add commands and flags; output layout and message wording are not stable.

### Core command hierarchy and syntax

Every command accepts `-config PATH` or `--config PATH`, default `config.yaml`.
`provider` has the alias `providers`; `<name>` completes from presets for `add` and from configured providers for `show`.

```text
Diagnose
  spillway doctor [-config PATH] [--no-probe]                      stable

Manage
  spillway provider list [-config PATH]                            stable
  spillway provider show <name> [-config PATH]                     stable
  spillway provider add  [<name>] [-config PATH] [--key-env VAR]   experimental in v1.1.x
                         [--attest-free-tier] [--base-url URL]
                         [--tier TIER | --no-tier] [--dry-run] [--yes]
```

Rules:

- `provider add` is additive: with every choice given by flags it writes without a prompt; in a terminal with missing choices it asks through Huh accessible mode and confirms the preview once.
- With `--yes`, a choice that has no flag value and no safe default is a usage error naming its flag (exit 2), as in `init`; with `--yes`, `<name>` is required.
- `--dry-run` prints the preview and exits 0 without writing or backing up.
- After a write, the command says `Spillway reads config only at startup; restart spillway serve -config <absolute path> to apply.`
- `provider add` is labelled `(experimental)` in its help and in the docs; it may change its flags in v1.2, where it either becomes stable or changes under a recorded decision.
- Exit codes: 0 success, warnings allowed; 1 failure, refusal or any failed doctor check; 2 usage error.

### Core package design

No new package.
Config editing lives in `internal/config`, which owns the schema; commands live in `internal/cli`.

`internal/config` (`document.go`, `edit.go`, `commit.go`, `commit_windows.go`, `commit_other.go`):

```go
// Document is a config file read for editing. It keeps the exact bytes so an
// edit changes only the lines it touches.
type Document struct{ /* resolved path, data, sha256 digest, mode, newline, BOM */ }

// OpenDocument reads path, following symlinks to the real file, and parses it
// without expanding environment references.
func OpenDocument(path string) (*Document, error)

// Path returns the resolved absolute path that Commit replaces.
func (d *Document) Path() string

// Edit returns an empty ordered edit of d.
func (d *Document) Edit() *Edit

// Edit is an ordered set of changes to one Document.
type Edit struct{ /* ... */ }

// ProviderEntry is a provider to add. It has no key field, so a key value
// cannot be written through it.
type ProviderEntry struct {
	Name     string // preset name
	KeyEnv   string // variable name, written as "${KeyEnv}"; empty for presets without keys
	BaseURL  string // empty keeps the preset default
	FreeTier bool   // free-tier attestation, groq and gemini only
}

func (e *Edit) AddProvider(p ProviderEntry) error
func (e *Edit) AppendTierModel(tier, modelRef string) error

// Result applies the edit, validates the new file with the normal parser and
// a unique placeholder per referenced variable, and proves that only the
// intended values changed.
func (e *Edit) Result() (Change, error)

// Change is a validated edit ready to preview or commit.
type Change struct{ /* before, after, hunks, secrets for preview redaction */ }

// WritePreview writes a unified-diff style preview with local key values redacted.
func (c Change) WritePreview(w io.Writer) error

// CommitOptions controls backups.
type CommitOptions struct {
	Now         func() time.Time
	KeepBackups int // most recent backups kept; 5 by default
}

// CommitResult reports where the old file was saved.
type CommitResult struct {
	Path, BackupPath string
	ModeTightened    bool
}

// Commit backs up the current file and atomically replaces it with c.
func (d *Document) Commit(ctx context.Context, c Change, o CommitOptions) (CommitResult, error)

// ErrConcurrentEdit reports that the file changed after OpenDocument read it.
var ErrConcurrentEdit = errors.New("config changed since it was read")

// LayoutError reports a file layout that an edit will not rewrite, with the
// YAML snippet the user can add by hand.
type LayoutError struct {
	Path    string // YAML path such as tiers.free.models
	Line    int
	Reason  string
	Snippet string
}
```

### Config mutation design (ADR 0025, written in C3)

Editing strategy: locate with the `yaml.Node` tree, change bytes by splicing whole lines.

- `OpenDocument` keeps the original bytes and a node tree with line and column positions.
- An operation finds its target node, computes the lines it occupies (from its start line to the line before the next sibling, excluding trailing comment and blank lines that belong to that sibling), and inserts lines at the indentation of existing siblings.
- New lines use the file's newline (LF or CRLF) and `"${VAR}"` quoting like `init`; a UTF-8 BOM is preserved.
- Everything outside the inserted lines stays byte-identical, including comments, blank lines, key order and quoting.
- An operation refuses with a `LayoutError`, and the CLI prints the exact snippet to add by hand, when its target container is in flow style (`providers: {groq: {...}}`, `models: [a, b]`), uses anchors, aliases or merge keys, or the file has more than one YAML document.
  `init` writes block style, so the main journey is always editable.
- `Result` parses the new bytes with `ParseWithEnv` and a lookup returning `placeholder-<VAR>`, unique per variable so two `${VAR}` local keys never look like duplicates.
- `Result` then proves intent: it decodes the old and new bytes into generic trees without expansion, applies the intended change to the old tree in memory, and requires equality; any difference is an internal error and nothing is written.
- An edit whose result fails validation is rejected and the file is untouched; the error names the field, never a value.

Write path (`Commit`):

1. Re-read the resolved file and compare its sha256 with the digest from `OpenDocument`; a difference returns `ErrConcurrentEdit` with `config.yaml changed while this command ran; rerun it`.
   This optimistic check is the only concurrency control, and the ADR records the remaining millisecond window.
2. Write a backup `<name>.<UTC yyyymmddThhmmssZ>.bak` next to the file with `O_EXCL`, mode 0600, and fsync it.
   Keep the 5 newest backups that match exactly this pattern; never touch other files.
   The output says backups are owner-only and contain local keys.
3. Create a temp file in the same directory with `os.CreateTemp(dir, "."+name+".spillway-*")`, mode 0600, then write, fsync and close it.
4. Replace:
   - Unix: `os.Rename` over the target, then fsync the directory.
   - Windows: `ReplaceFileW` through `windows.NewLazySystemDLL("kernel32.dll")` (no cgo), which keeps the original file's security descriptor and attributes, unlike `MoveFileEx`, which would give it the directory's inherited ACL.
     Sharing violations from editors or antivirus scanners are retried up to 5 times over about 1 second, then reported with the path and the advice to close programs holding the file.
5. On any failure the temp file is removed and the original stays in place; the backup is kept.

Permissions: the new file is 0600 on Unix, and the output says when a broader original mode was tightened; Windows modes are not enforced (ADR 0017), and the ACL is kept.
Symlinks: the edit targets the resolved file, so a dotfiles link stays a link.
Read-only and bind-mounted files: `EROFS`, `EACCES` and `EBUSY` (a single-file Docker bind mount cannot be renamed over) produce `config.yaml is read-only or mounted into a container; edit it on the host with the host's spillway`.
The running server is never signalled or reloaded.

Rejected alternatives: re-encoding the whole node tree (re-indents, drops blank lines, moves comments); regenerating from a parsed `Config` (writes `[REDACTED]` or real secrets, loses comments); regex edits (cannot find container boundaries); lock files (stale after crashes, no protection from editors).

ADR 0025 also records the experimental status of `provider add` for v1.1.x, amending the experimental-command list of ADR 0015, and amends ADR 0017's "overwriting an existing config needs a new ADR" for explicit management commands only; `init` still never overwrites.

### Diagnostics design (ADR 0026, written in C5)

`doctor` is read-only and stable.
It reports each check as ok, info, warn or fail, never prints a secret value, and makes no provider call.

1. Executable: path, version, install channel, and whether `spillway` on `PATH` resolves to another file (scanning `PATH` like `exec.LookPath`; other executables are never run).
2. Config: absolute path and whether it was the default or `-config`; existence, size, symlink target; mode on Unix (warn when group or others can read); validity with placeholder values; the configured provider names.
3. Variables referenced by providers and local keys: whether each exists in this process, and on Windows whether it exists for the user or the machine (registry metadata only, read-only, never the value; resolved question 1).
   The output distinguishes "configured for your user or machine but not available in this terminal" from "not configured anywhere".
4. Shell guidance for an unset variable, informational and offline, never containing a value or a placeholder for one, so no key reaches command arguments, shell history, logs or files Spillway writes (resolved question 4):
   - PowerShell: `$env:VAR = [Net.NetworkCredential]::new('', (Read-Host -AsSecureString 'provider key')).Password` for this terminal; `[Environment]::SetEnvironmentVariable('VAR', $env:VAR, 'User')` after that, then a new terminal, for persistence.
   - bash and zsh: `read -rs VAR && export VAR` for this terminal; for persistence, a secret manager, or a private file (`chmod 600`) sourced from the shell profile.
   - fish: `read -s VAR; set -gx VAR $VAR` for this terminal; `set -Ux VAR $VAR` for persistence.
   - The shell is chosen from `GOOS` and the base name of `$SHELL`; unknown shells get the POSIX form.
   - The helper is shared with 0009 T04's missing-variable hint so both say the same thing.
5. Provider key checks, only on values already present in this process, never printing any character, length or hash of the value (resolved question 3):
   - fail on certain mistakes that no provider format allows: surrounding quotes, leading or trailing whitespace or newline, a `Bearer ` prefix, a literal `${`, or a documented placeholder such as `<your-provider-key>`;
   - warn, advisory only, when the value lacks the provider's public, documented prefix (Gemini `AIza`, Groq `gsk_`, OpenRouter `sk-or-`); the message names that public prefix only.
   A key is never failed on its provider-specific format alone, because providers may change their formats.
   This reveals one bit about a provider key (whether it has the usual public prefix); it reveals nothing about local keys.
6. Local keys: each entry's name, access (chat or dashboard), source (`literal at line N` or `${VAR}` set or not set), and which entry client apps use.
   No value, prefix, suffix, fingerprint, hash or length is shown.
   The one exception is an advisory warning that a key is shorter than 32 characters, which never states the actual length and never rotates or changes the key (resolved question 2).
7. Listen address, skipped with `--no-probe` (detailed below).
8. Store: absent, or the directory exists and `store.Inspect` reports a schema this binary supports; a newer schema repeats 0009 T04's recovery text and never suggests deleting the file.
9. Install channel and offline upgrade guidance (see "Install channels").

#### Listen-address diagnosis without a new header

`doctor` never sends a local key, so it needs no proof that the listener is Spillway; it only needs to tell users whether the port is free, held by something that is clearly not Spillway, or held by something that answers like Spillway.

1. Probe first, unauthenticated, on the configured address (wildcard hosts map to `127.0.0.1` and `[::1]`; `127.0.0.1` and `localhost` also probe `[::1]`, because `localhost` may resolve to IPv6 where another program answers):
   - `GET /healthz` must return 200, `text/plain; charset=utf-8` and exactly `ok`;
   - `GET /v1/models` without `Authorization` must return 401 JSON with `error.type` `authentication_error` and `error.code` `invalid_api_key`;
   - on a loopback listen address, `GET /healthz` with `Host: doctor.invalid` must return 403 JSON with `error.code` `host_not_allowed`, a Spillway-specific code checked before authentication.
2. Classification:
   - every check matches: "answers like Spillway", reported as info with the startup-summary comparison advice;
   - any check differs: "not Spillway", reported as fail with status and content type only, never the body;
   - connection refused: nothing listening on that address.
3. Then try `net.Listen` on the address and close it immediately.
   A bind can succeed on Windows while another program's wildcard listener still answers some clients, so both results are reported.
4. Guidance names OS-specific owner lookups (`Get-NetTCPConnection -LocalPort N -State Listen`, `lsof -nP -iTCP:N -sTCP:LISTEN`, `ss -ltnp 'sport = :N'`) and `docker ps --filter publish=N`, and suggests another loopback port with the matching client base URL.
   It never suggests a non-loopback address, removing local keys or stopping a process.

Transport rules: `Proxy: nil`, no redirects followed, 2 seconds per request, at most 4 KiB read from any body, only the configured listen address.

Why no identity header is needed: a header could be faked by any local program, so it would not make sending a key safe; the diagnosis needs only a reliable "not Spillway" answer, which the existing stable responses give.
Evidence 6 (a Spring Boot 403 on `/healthz`) fails the first check.
The cost is that another OpenAI-compatible gateway on loopback with a Host allowlist could be reported as "answers like Spillway"; since no key is sent, that misreport is harmless and the advice still points to the startup summary.

Wrong config (evidence 4) without a key: `doctor` prints the absolute config path and providers, and C6 adds `providers=[...]` to the `serve` startup summary that 0009 T02 and T05 already give a config path and URLs; the user compares the two.
Automatic comparison is the deferred `status` command.

#### Windows registry metadata

`PersistentEnv` opens `HKCU\Environment` and `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment` read-only and calls `GetValue(name, nil)`, which returns only the size and type, never the data.
This is offline, local and read-only, and it is the only way to explain evidence 3 ("set for your user, but this terminal started earlier").
It goes one step beyond the process environment; the owner approved it (resolved question 1), and ADR 0026 records that approval and its limits.

### Install channels and offline upgrade guidance (in C5)

`doctor` detects the channel offline and prints the matching instruction; it never downloads, checks for a release or replaces anything.

| Channel | Detection | Instruction |
|---|---|---|
| Release archive | ldflags version is a `v`-prefixed semver (0009 T02), build info has `-tags=dashboardassets`, `vcs.modified=false` | download a newer archive from the releases page, verify `checksums.txt` and `gh attestation verify` as in `docs/install.md`, replace the printed path |
| `go install` | ldflags version `dev` and build info `Main.Version` is a module version | `go install github.com/Polqt/spillway/apps/spillway@vX.Y.Z` |
| Docker image | `GOOS=linux` and executable path `/spillway` | `docker pull ghcr.io/polqt/spillway:X.Y.Z` and update the tag in `docker run` or compose |
| scoop | path contains `\scoop\apps\` or `\scoop\shims\` | `scoop update spillway`; not an official channel (ADR 0016) |
| Homebrew | path under `/opt/homebrew/`, `/usr/local/Cellar/` or `/home/linuxbrew/.linuxbrew/` | `brew upgrade spillway`; not an official channel |
| Local or unknown build | anything else, including `make build` `git describe` versions | rebuild from source or install a release archive |

The releases page URL is printed text, not a request; C5 adds it to a separate printed-only set in `tests/e2e/egress_test.go`, not to the egress allowlist.

### Compatibility analysis

- Existing commands, flags, exit codes, help aliases and single-dash flags are unchanged; C1 runs the existing `tests/cli` suite unchanged and adds a table of every v1.0 command and flag.
- `init` keeps `O_EXCL`; only its existing-config message (wording not stable) adds `To add a provider to it, run spillway provider add <name> -config <path>.`

### Security analysis

| Property | Mechanism | Proven by |
|---|---|---|
| Provider key values are never written | `ProviderEntry` has no key field; `--key-env` takes a validated variable name; `Result` re-checks every provider `api_key` is a `${VAR}` reference | `TestProviderAdd_WritesOnlyEnvReference`, `TestProviderAdd_KeyLikeKeyEnvRefusedWithoutEcho` |
| Secret values are never printed | values are read only into `redact.Secret`; checks return closed results | canary `sk-test-canary-...` provider and local keys absent from stdout, stderr, config previews and backups in every command test |

| Invalid results are never written | `Result` validates and verifies intent | `TestEdit_InvalidResultRejectedFileUntouched`, `TestEdit_ResultRejectsUnintendedChange` |

### ADRs

Core (written by core tickets, after this approval):

1. **ADR 0025: CLI commands may edit an existing config** (written in C3).
   Decision: the line-splice strategy, placeholder validation, intent verification, preview, timestamped 0600 backups keeping 5, digest re-check, same-directory temp file and atomic replace (rename and directory fsync on Unix, `ReplaceFileW` on Windows), symlink resolution, refusal of flow style, anchors and multi-document files, rejection of invalid results; never marshalling a parsed `Config`; never writing a provider key value; `provider add` experimental for v1.1.x.
   Alternatives: whole-tree re-encode, regenerate from `Config`, regex edits, lock files.
   Amends ADR 0017 (overwriting an existing config) and ADR 0015 (experimental command list).
2. **ADR 0026: Local diagnostics** (written in C5).
   Decision: `doctor` makes no provider call and sends no key; it probes only the configured listen address with unauthenticated requests through a no-proxy, no-redirect, bounded client, and classifies listeners by Spillway's existing stable responses; no new header; environment presence (including Windows registry metadata) is reported without values; shell guidance is informational and offline; provider key checks never reveal characters; local keys are shown by name, access and source only.
   Alternatives: a new identity header (rejected: it is spoofable and unnecessary when no key is sent); version on `/healthz` (fingerprinting); `/v1/models` with a key (sends a key, calls providers); OS APIs to find the port owner (platform code and privileges; printed commands instead).
   Records why plan 0009's rejection of `doctor` no longer holds.

Deferred (numbers assigned when written; not approved for implementation):

- **Local key creation and rotation display**: a key is displayed once at `key create` or `key rotate`, after confirmation, to stdout only, with a warning to save it securely; existing keys are never displayed; no clipboard; no prefix or fingerprint unless separately approved.
  Amends ADR 0017.
- **Explicit provider tests**: contacts only the named configured provider; model listing by default; a one-token chat only with a spend warning and confirmation; never prints upstream bodies; never changes quota state.
  Follows ADR 0013.
- **Gateway status**: how `status` can learn the running server's providers without sending a key to an unverified listener; it needs its own verification design before any key is sent.
- **Signed release checksums**: Ed25519 signature over `checksums.txt`; must first document key generation and custody, trusted public-key distribution (embedded in binaries and published out of band), rotation, and compromise recovery including how already-installed binaries stop trusting a compromised key.
  Amends ADR 0016.
- **Standalone self-upgrade**: requires the signed-checksums ADR, a separate Windows executable replacement design, and an owner amendment of the outbound-call hard rule; no agent may make that amendment.

### Glossary additions (C7)

- **Install channel**: how a Spillway binary was installed (release archive, `go install`, Docker image, or an unofficial package manager), which decides how it is upgraded. _Avoid_: distribution.
- **Config backup**: the owner-only copy of the config a management command saves before replacing it. _Avoid_: snapshot.
- **Experimental command**: a command whose flags and behavior may change in the next minor release; currently the `eval*` commands and `provider add`. _Avoid_: beta.

### Test strategy across Windows, Linux and macOS

CI already runs `make check` with `-race` on ubuntu, macos and windows on two Go versions (ADR 0016), so every test runs on all three unless marked.

- Pure logic (all OS): splicing, intent verification, layout refusals, CRLF and BOM preservation, preview redaction, shell guidance for every `GOOS` and shell through `Options`, channel detection from injected paths and build info, provider key checks.
- File system (all OS): atomic replace, backup naming and pruning with injected `Now`, digest re-check, failed-replace rollback, symlink resolution (on Windows without the symlink privilege the test detects the error and calls `t.Skip` naming the missing privilege).
- Unix only (`//go:build !windows`): 0600 modes on the file and backups, the mode-tightened notice, directory fsync, `EROFS` and `EBUSY` mapping through an injected rename error.
- Windows only (`//go:build windows`): `ReplaceFileW` keeps a custom DACL set by the test; a target held open without `FILE_SHARE_DELETE` makes the bounded retry give up cleanly under `testing/synctest`; the real `PersistentEnv` returns not found for a random name.
- Network (all OS): probes against `httptest.Server` fakes (the real Spillway handler, a Spring Boot style 403, an OpenAI-shaped 401 server without a Host check, a raw TCP listener that closes, a redirecting server); `[::1]` cases detect missing IPv6 loopback and call `t.Skip` with the reason.
- Binary end to end (all OS, `tests/e2e`): `init`, `provider add`, `check`, `serve` on an ephemeral port, `doctor` against the running server, canary keys absent from every stream.

## Hard-rule check

- No quota evasion: `provider add` refuses a configured provider and points to a plan upgrade or another provider; nothing allows a second instance, key pooling or rotation.
- No credential collection: no command prompts for or stores a provider key; `--key-env` takes a variable name only.
- Secrets never leak: no command prints a provider or local key value, prefix, fingerprint or hash; previews redact local keys; `doctor` sends no key anywhere; canary tests cover every output, preview and backup name; inbound `Authorization` handling is untouched.
- Single binary, no cgo: no new module; `golang.org/x/sys` v0.48.0 (2026-08-31) and `github.com/mattn/go-isatty` v0.0.24 (2026-07-23) are already in the module graph through `modernc.org/sqlite` and become direct; `ReplaceFileW` is loaded with `NewLazySystemDLL`; `CGO_ENABLED=0 go build ./...` stays in `make lint`.
- Local by default: no command changes `server.listen`; port hints suggest loopback ports; probes reach only the configured local listen address; no outbound call is added, and upgrade stays offline guidance.
- OpenAI compatibility: no `/v1/*` or `/healthz` change; the missing Responses API is documented.

## Deferred work (not approved for implementation)

These designs are kept so nothing is lost.
Each needs its own plan revision, owner approval and, where named, a new ADR before ticketing.

### Approved decisions that bind deferred work

- Local keys are displayed once, only at explicit creation or rotation, after confirmation, with a warning to save the credential securely; existing keys are never displayed by `show`, `list`, logs, config printouts or dashboard responses; there is no `key reveal`.
- Local key prefixes, fingerprints and hashes are not shown unless a documented security analysis is approved.
- `provider remove` displays every affected model reference, tier, `models:` and `pricing:` entry, `router.auto`, `router.difficulty` and `router.classifier` reference, requires confirmation, and rejects any change whose result would be invalid (for example an empty tier or a dangling tier name).
- Commands that may spend money are deferred; a provider test that spends needs a warning and confirmation.
- No networked upgrade or `upgrade --check` while the outbound-call hard rule is unchanged.
- Ed25519-signed checksums are the approved prerequisite for trusted self-upgrade; key management, trusted public-key distribution, rotation and compromise recovery are documented before implementation; checksums alone are insufficient.
- Windows executable replacement is handled by its own design and ticket; no in-place overwrite of a binary on any OS.
- Config-mutating commands start experimental for one release.

### CLI management phase 2 (target: v1.2 or a later minor, or a maintenance milestone)

- D1 `key list`: names, access, source and location, the same view `doctor` gives; no value, prefix or hash.
- D2 `key create <name> [--dashboard]` and `key rotate <name>`: generate with `generateLocalKey`, store as a literal (ADR 0017), and after confirmation display the new key once on stdout with a stderr warning to save it securely; nothing displayed if the write fails; `${VAR}` keys cannot be rotated (change the variable instead).
  Needs the deferred local key display ADR and `Edit.AddLocalKey` and `Edit.ReplaceLocalKey`.
- D3 `key revoke <name>`: confirmation; refuses the last key (ADR 0003); warns on the last dashboard key; notes that older backups still contain the revoked key until pruned.
- D4 `provider remove <name>`: preview of every affected reference as above, confirmation (`--yes` when not interactive), rejection of invalid results; needs `Edit.RemoveProvider`.
- D5 `model list [--tier] [--provider]`, `tier list`, `tier show <name>`: read-only, offline views of declarations, prices, zero-spend eligibility, tier order and `router.auto` position.
- D6 `status`: identity and loaded-provider comparison for a running server; requires a design that never sends a local key to an unverified listener, recorded in the deferred gateway status ADR.
- D7 `provider test <name>`: zero-spend model listing through the provider adapter, with classified outcomes (key rejected, rate limited, not found, provider error, unreachable, timeout), no upstream body printed, and the key sent only to its own provider; OpenRouter's listing does not check the key, so it says so.
- D8 `provider test <name> --chat`: one non-streaming chat with `max_tokens: 1`, a spend warning and confirmation; local providers skip the confirmation.

### Self-upgrade milestone (no target; blocked on owner decisions)

- U1 Signing prerequisites document and ADR: key generation and custody in an environment-protected GitHub secret with owner approval, public-key distribution (embedded in binaries and published in `docs/install.md` and `SECURITY.md`), scheduled and emergency rotation (ship the next public key one release ahead), and compromise recovery (revocation list in new releases, advisory, and manual re-install instructions for binaries that still trust the old key).
- U2 Signed checksums: GoReleaser `signs:` over `checksums.txt` producing `checksums.txt.sig`; verification with `crypto/ed25519` in a new `internal/release` package; the artifact workflow verifies the signature; users can verify with `openssl pkeyutl -verify`.
- U3 Hard-rule amendment for user-invoked release checks: only the owner can change AGENTS.md; until then `upgrade --check` is not planned.
- U4 `upgrade --check` and download: HTTPS to `github.com` release assets only, no identifiers sent, bounded sizes, signature and checksum verified, only the binary extracted, no path traversal, stable releases only unless `--pre`, no silent downgrade.
- U5 Unix replacement: write `spillway.new` beside the binary with mode 0755, fsync and rename over (a new inode also avoids macOS arm64 killing a binary changed in place); never elevate; refuse non-archive channels with the instruction from the install-channel table.
- U6 Windows executable replacement, separately: rename the running `spillway.exe` to `spillway.exe.old`, move the verified file into place, roll back on failure, remove a leftover `.old` on the next run; refuse when the directory needs elevation; a running `serve` keeps the old code until restarted.

## Manual verification (core)

Run with the release-candidate binary on Windows 11 with PowerShell 7 and with Windows PowerShell 5.1, Git Bash on Windows, Linux with bash, and macOS with zsh.

```sh
spillway init -yes -providers groq -attest-free-tier groq -config ./t.yaml
spillway provider add groq -config ./t.yaml              # refusal, exit 1, file unchanged
spillway provider add gemini --attest-free-tier --tier free -config ./t.yaml --dry-run
spillway provider add gemini --attest-free-tier --tier free -config ./t.yaml
spillway check -config ./t.yaml                           # config OK, gemini present
spillway provider list -config ./t.yaml                   # variable presence, no values
spillway provider show gemini -config ./t.yaml
spillway doctor -config ./t.yaml                          # unset variable guidance for this shell
spillway serve -config ./t.yaml                           # in another terminal; startup lists providers
spillway doctor -config ./t.yaml                          # listen address answers like Spillway
```

Expected: the write leaves one `t.yaml.<timestamp>.bak`; `server.api_keys` lines are unchanged; no key value, prefix or hash appears anywhere.

Evidence reproductions:

- Windows: set a variable with `[Environment]::SetEnvironmentVariable(..., "User")`, run `spillway doctor` in the same terminal; expect "set for your Windows user, open a new terminal".
- Any OS with Docker: `docker run --rm -d -p 8080:80 nginx:1.27`, keep Spillway stopped, run `spillway doctor`; expect "not Spillway", owner-lookup commands and a loopback port suggestion; stop the container.
- Serve `config.yaml`, add a provider to it without restarting, run `spillway doctor`; expect the "answers like Spillway" advice and a startup summary without the new provider.
- Docker with a bind-mounted config: `docker run --rm -v "$PWD/t.yaml:/etc/spillway/config.yaml:ro" ghcr.io/polqt/spillway:1.1.0-rc.1 provider add mock -config /etc/spillway/config.yaml`; expect the read-only explanation.
- Linux and macOS: `ls -l t.yaml*` shows `-rw-------` for the config and the backup.
- Windows: `icacls t.yaml` shows the same ACL before and after the edit.

## Resolved questions (owner, 2026-10-20)

No open questions remain.

1. Windows registry metadata: approved.
   `doctor` and `provider list` may check whether a provider variable exists in this process, the Windows user environment or the machine environment.
   They never read, print or persist a value, stay read-only, and distinguish "configured but not available in this terminal" from "not configured".
2. Weak local key warning: approved.
   `doctor` warns when a local key is shorter than 32 characters, without stating the actual length, prefix, suffix or value.
   The warning is advisory only; it never fails `doctor` and never rotates or changes a key.
3. Provider key format hint: approved, advisory only.
   Format checks run only on credentials already present in this process and never print key fragments.
   No key is failed on its provider-specific format alone, because providers may change their formats; only the certain mistakes in diagnostics check 5 fail.
4. History-safe shell guidance: approved.
   `doctor` and 0009 T04 share one helper for PowerShell and POSIX shells.
   No guidance puts a credential in command arguments, shell history, logs or files Spillway writes.
5. `provider add` stability: approved conditionally.
   Stable status is targeted for v1.2 only after its flags, behavior, security tests and compatibility have been verified.
   It is not promoted automatically because its flags did not change.
6. Self-upgrade: deferred indefinitely.
   No release target is assigned while the outbound-network rule stays unchanged.
   Verified, signed release metadata stays a prerequisite before self-upgrade is reconsidered.
