# v0.2 Spillover: Free-Tier Autopilot

Status: approved (2026-10-14; every decision accepted with its recommended option; ADR 0005 and ADR 0006 accepted)
Milestone: v0.2

## Goal

A client app sends `model: "spillway/<tier>"` and Spillway serves it from the first candidate in that user-named tier that is eligible right now, spilling over to the next candidate on a rate limit, a provider failure or a timeout, as long as no byte of the response has reached the client.
Tiers are zero-spend by default: a zero-spend tier can only contain models that are free by a rule Spillway can state (local provider, OpenRouter `:free` variant, or a provider key the user attests is on a free plan), and `spillway check` refuses anything else.
Candidates that just failed are skipped for a cooldown (honouring `Retry-After`), repeated failures open a circuit breaker, and when no candidate is left the client gets one clear OpenAI-shaped error that names each candidate and why it was skipped.
Routing is deterministic: same config, same clock and same failure history give the same candidate order.

## Current state (inspected 2026-10-14, HEAD 61f3a53)

- `internal/api/chat.go` resolves one model reference to one provider and makes exactly one call; `spillway/<tier>` and `auto` return 404 pointing at v0.3.
- `internal/api/stream.go` writes SSE headers only when the first chunk arrives, so a failure from `ChatStream` or from the first `Recv` is still a plain HTTP error. This is the natural spillover commit point and needs no restructuring.
- `providers.ChatRequest.RawBody` is immutable and `openaicompat.requestBody` swaps only the `model` field, so one decoded request can be replayed to several candidates.
- Errors carry a kind (`ErrRateLimited`, `ErrUpstreamUnavailable`, `ErrUnauthorized`, `ErrBadRequest`, `ErrModelNotFound`) and, for 429 only, a `RetryAfterError`. Client cancellation stays `errors.Is(err, context.Canceled)`.
- `config` rejects `tiers:` with "not supported until v0.2"; there is no `internal/quota`.
- Two stream-fidelity gaps in `openaicompat.sseStream`, both deviations from the v0.1 plan (section "SSE reader"), become correctness bugs once spillover exists:
  1. A `data: {"error":{...}}` event is relayed as an ordinary chunk. OpenRouter answers some failures with HTTP 200 followed by an error event, so today the client receives the error as a chunk and then `[DONE]`; with spillover, a first-event error must be spillable instead.
  2. EOF without `data: [DONE]` returns `io.EOF`, so a truncated stream counts as success.
- 402 maps to `ErrBadRequest` (the `default` branch), and Gemini's `RetryInfo.retryDelay` is ignored, so Gemini 429s carry no retry time.

## Provider constraints (researched 2026-10-14)

| Provider | Free signal Spillway can see | Limit scope | Retry information |
|---|---|---|---|
| Ollama, mock | Local, always free | None | n/a |
| OpenRouter | Model id suffix `:free`; free variants are never billed | Account-wide for all `:free` models: 20 RPM, and 50 requests/day (1000 after 10 credits purchased); upstream capacity 429s per model | `Retry-After` on 429; 402 on negative balance, even for free models, with `error.metadata.limit_source` |
| Groq | None in the API: free vs Developer plan is account state | Per model, per organization: RPM, RPD, TPM, TPD | `retry-after` on 429; `x-ratelimit-{limit,remaining,reset}-{requests,tokens}` on every response (requests = per day, tokens = per minute; reset like `2m59.56s`) |
| Gemini | None in the API: the tier belongs to the Google Cloud project, and enabling billing silently moves the same key to a paid tier | Per project, per model: RPM, TPM, RPD; RPD resets at midnight Pacific | 429 `RESOURCE_EXHAUSTED`, retry delay in the error body's `google.rpc.RetryInfo` detail (`retryDelay: "34s"`); fixture shape to be confirmed against a real 429 in manual verification |

Sources: openrouter.ai/docs/api-reference/limits, console.groq.com/docs/rate-limits, ai.google.dev/gemini-api/docs/rate-limits.

Consequence: "verified free" is only possible for local providers and OpenRouter `:free` ids.
For Groq and Gemini it can only be the user's attestation, and the plan says so rather than pretending otherwise (Decision 2, ADR 0005).
Privacy note for the docs: Gemini's free tier and some OpenRouter free endpoints may use prompts for training; free-first routing sends prompts under those terms.

## Scope

In (MVP):
- `tiers` config: user-named ordered lists of model references; list order is the priority.
- Zero-spend by default per tier, `allow_spend: true` to opt out; `free_tier: true` attestation on `groq` and `gemini`; static eligibility checked by `serve` and `check`.
- `spillway/<tier>` resolves in `/v1/chat/completions` and is listed in `/v1/models` (pulled forward from v0.3, Decision 3).
- Spillover, non-streaming and streaming, before the first byte reaches the client, on: 429, 402, 5xx, transport errors and timeouts, 401/403 (provider key rejected), 404 (model gone).
- No spillover on 400/413/422 or client cancellation.
- `internal/quota`: in-memory cooldowns and a consecutive-failure circuit breaker, keyed per candidate (provider-wide for key and payment failures), `Retry-After` and Gemini `retryDelay` honoured and clamped.
- Basic quota awareness: Groq `x-ratelimit-remaining-*: 0` puts the model into cooldown until the matching reset, before a 429 happens.
- Exhaustion error: 429 with `Retry-After` when every candidate is cooling down with a known resume time, else 503; the message lists each candidate and its reason.
- Stream fidelity fixes in `openaicompat` (error events, EOF without `[DONE]`).
- Access log gains `tier` and `attempts`; each skipped or failed attempt logs one scrubbed line.
- ADR 0005 (zero-spend eligibility) and ADR 0006 (spillover policy), written at approval; GLOSSARY and CONTEXT updates; example configs with tiers.

Deferred:
- `auto`, capability detection (tools, vision, context length), `x-spillway-route`: v0.3. Until then a tier that mixes capabilities can fail a tools request with a 400 that does not spill (Risk 4).
- User-declared RPM/RPD limits with local request counting, and persisted quota state: v0.4 with SQLite, because in-memory daily counts reset on restart and would be wrong exactly when they matter.
- OpenRouter catalog pricing verification (`/models` `pricing` all zero), model-list caching: v0.4 with budgets and pricing.
- Half-open single-probe breakers, provider-wide transport breakers, latency or weighted routing (non-deterministic), a separate first-byte timeout, configurable cooldown constants: only if real use shows the need.
- Spillover for direct model references (`groq/x`): never planned; an explicit model reference means the client chose that model. Direct references neither consult nor update the tracker in v0.2.
- `/v1/embeddings`, Mistral, Anthropic, OpenAI adapters.

## Design

### Config

```yaml
providers:
  groq:       { api_key: "${GROQ_API_KEY}", free_tier: true }   # I attest this account has no paid plan
  gemini:     { api_key: "${GEMINI_API_KEY}", free_tier: true } # I attest this project has no billing
  openrouter: { api_key: "${OPENROUTER_API_KEY}" }
  ollama:     { base_url: "http://localhost:11434" }

tiers:
  free:                                   # zero-spend: the default
    models:
      - groq/llama-3.1-8b-instant
      - gemini/gemini-2.5-flash
      - openrouter/meta-llama/llama-3.3-70b-instruct:free
      - ollama/llama3.2:3b
  smart:
    allow_spend: true                     # explicit opt-in to paid models
    models: [openrouter/anthropic/claude-sonnet-4.5, groq/llama-3.3-70b-versatile]
```

Validation (each error names the YAML path and how to fix it):
- Tier names match `[a-z0-9-]{1,64}`; `auto` is reserved.
- `models` holds 1 to 16 model references, each parsing with `providers.ParseModelRef`, each naming a configured provider, no duplicates within a tier. The same model may appear in several tiers and then shares one health state.
- In a tier without `allow_spend: true`, each model must be zero-spend eligible: provider `ollama` or `mock`; provider `openrouter` with an upstream model ending in `:free`; provider `groq` or `gemini` with `free_tier: true`. Otherwise: `tiers.free.models[1]: gemini/gemini-2.5-pro is not zero-spend eligible: set providers.gemini.free_tier: true only if its Google Cloud project has no billing, or set tiers.free.allow_spend: true (ADR 0005)`.
- `free_tier` is accepted only on `groq` and `gemini`: OpenRouter eligibility is per model, local providers are always free.
- `tiers` is optional; without it v0.1 behaviour is unchanged.
- `serve` logs one info line at startup listing providers with `free_tier: true` as attested, so a wrong attestation is visible.

The simple list form (`free: [a, b]`) is rejected in favour of one mapping form: one shape, no custom unmarshaller, and room for `allow_spend`.

### Package layout and dependency direction

```
internal/quota  -> providers            (new)
internal/api    -> providers, redact     (gains a consumer-side tracker interface)
internal/cli    -> + quota               (wiring)
internal/config -> unchanged imports     (tiers, free_tier, eligibility)
```

`internal/router` is not created: v0.2 has no routing logic beyond "tier order, minus unavailable candidates", which fits in the api package's chat path.

### internal/quota

One deep type, all state in memory, guarded by one mutex, keys bounded by the configured candidates.

```go
type Options struct {
    Now        func() time.Time
    Candidates []providers.ModelRef // every model in every tier; unknown refs are ignored
}
func New(o Options) (*Tracker, error)

// Available reports whether ref may be tried now and, if not, until when and why.
func (t *Tracker) Available(ref providers.ModelRef) (ok bool, until time.Time, reason string)
// Observe records the outcome of one attempt. err nil is success; context.Canceled is ignored.
func (t *Tracker) Observe(ref providers.ModelRef, err error, hint providers.RateLimit)
```

Rules, all constants in the package (not configurable in v0.2):

| Outcome | Scope | Cooldown |
|---|---|---|
| success | candidate | consecutive failures reset to 0; a `hint` with requests or tokens remaining 0 cools until that reset |
| `ErrRateLimited` with retry time | candidate | the retry time, clamped to [1s, 24h] |
| `ErrRateLimited` without | candidate | 15s doubling per consecutive 429, cap 10m |
| `ErrPaymentRequired` (402) | provider | retry time if given, else 15m |
| `ErrUnauthorized` | provider | 15m, logged at error level |
| `ErrModelNotFound` | candidate | 15m |
| `ErrUpstreamUnavailable` (5xx, transport, timeout, mid-stream failure) | candidate | breaker opens at 3 consecutive failures: 30s, doubling per further failure, cap 5m; a `Retry-After` on a 503 is honoured immediately |
| `ErrBadRequest`, `context.Canceled` | none | not recorded |

After a cooldown the candidate is simply available again; the next failure re-opens it with the doubled time because the consecutive count survives until a success.
This replaces a half-open probe state with no extra state; the cost is that concurrent requests at expiry may each try once, which on a local gateway is a handful of spilled requests (Deferred).

### internal/providers changes

- `ErrPaymentRequired` sentinel; `openaicompat` maps 402 to it with `Retry-After` when present.
- `RetryAfterError` is also produced for 503 with `Retry-After`.
- Gemini `classifyError` reads `retryDelay` from the `google.rpc.RetryInfo` detail.
- `RateLimit{RemainingRequests, RemainingTokens int; ResetRequests, ResetTokens time.Duration; Known bool}` on `ChatResponse` and returned by an optional `RateLimiter` interface on the stream, filled by `openaicompat` from Groq-style `x-ratelimit-*` headers; absent headers leave `Known` false.
- `sseStream`: a `data:` payload with a top-level `error` yields a typed provider error (kind from `error.code` when it is an HTTP status, else `ErrUpstreamUnavailable`), scrubbed; EOF without `[DONE]` yields `ErrUpstreamUnavailable` ("stream ended without [DONE]").

### internal/api: tier resolution and spillover

`api.Options` gains `Tiers map[string][]providers.ModelRef` and `Tracker tracker` (interface in `api` with `Available` and `Observe`).

Chat flow for `spillway/<tier>`:
1. Unknown tier: 404 `model_not_found` naming the configured tiers. `auto` keeps its v0.3 404.
2. For each candidate in tier order:
   - `Available` false: record the skip reason, continue.
   - Clear `X-Spillway-Provider`, `X-Spillway-Model` and `Retry-After` from previous attempts, set them for this candidate, call the provider.
   - Non-stream: success writes the body. Stream: success is the first `Recv` returning a chunk; from then on the response is committed and v0.1 streaming applies unchanged (a later failure is an error event and no `[DONE]`, and is still `Observe`d).
   - `r.Context().Err() != nil`: stop, no `Observe`, write nothing.
   - Otherwise `Observe(ref, err, hint)`; a spillable kind continues, `ErrBadRequest` answers the client as in v0.1.
3. Exhausted: if every candidate is unavailable with a known resume time, 429 `rate_limit_exceeded` with `Retry-After` = earliest resume (seconds, rounded up); otherwise 503 `type: api_error`, `code: no_candidate_available`.
   Message: `No candidate in tier "free" can serve this request: groq/llama-3.1-8b-instant rate limited (retry in 34s); gemini/gemini-2.5-flash circuit open (retry in 30s); ollama/llama3.2:3b unavailable.` Model references come from config, provider error text never appears (it stays in the scrubbed log).
4. `ErrPaymentRequired` on a direct model reference maps to 429 `insufficient_quota`, OpenAI's own shape for an account out of credit.

The response `model` field stays the upstream value (v0.1 Decision 6); `x-spillway-model` and `x-spillway-provider` name the candidate that served.
Attempts per request are bounded by the tier length (at most 16); each attempt is bounded by its provider `timeout`.

`/v1/models` appends one entry per tier, `id: spillway/<tier>`, `owned_by: spillway`, sorted with the rest.

### Hard-rule check

- No quota evasion: one provider key per provider is unchanged; spillover moves to a *different* candidate and never retries a candidate within one request; a cooldown is never shortened below the provider's `Retry-After`; two models on the same provider in one tier are separate models with separate published limits, not separate accounts.
- No credential collection, secrets never leak: no new secret; skip reasons and exhaustion messages are built from config model references and error kinds only; tests assert keys are absent from the exhaustion message, logs and headers.
- Single binary, no cgo: no new dependency.
- Local by default: unchanged; no new outbound call (no catalog fetch in v0.2).
- OpenAI compatibility: success responses are relayed verbatim; exhaustion uses the OpenAI error shape and statuses the SDKs already retry (429 with `Retry-After`, 503).

## Acceptance criteria and offline test scenarios

All offline: `httptest.Server` fixtures, the mock provider and in-test fake providers; time via `testing/synctest` and the injected clock.

- **Order and determinism.** A tier `[a, b, c]` where `a` returns 429 and `b` succeeds: `b` serves, `x-spillway-model` is `b`'s upstream model, the access log shows `tier=free attempts=2`. Running the same scenario 100 times in a loop yields the same candidate every time.
- **Spillable vs not.** Table over 429, 402, 500, 502, 503, transport refusal, per-attempt timeout (synctest), 401, 403, 404: spill. 400, 413, 422: no spill, client gets the v0.1 error, later candidates record zero calls.
- **Commit point.** Streaming: `a` fails in `ChatStream` → spill; `a` returns a 200 whose first event is an error → spill, the client sees only `b`'s chunks and one `[DONE]`; `a` sends two chunks then fails → no spill, error event, no `[DONE]`, `b` records zero calls.
- **Cancellation.** Client disconnects while `a` is in flight: `b` is never called and the tracker records nothing.
- **Cooldown.** `a` 429 with `Retry-After: 34`: the next request skips `a` without calling it; at 33s (synctest) still skipped; at 34s tried again. Without `Retry-After`: 15s, 30s, 60s on consecutive 429s, capped at 10m. `Retry-After: 999999999` clamps to 24h; garbage and negative values fall back to backoff.
- **Provider scope.** `groq` 401 cools every Groq candidate in every tier; Gemini candidates are unaffected.
- **Breaker.** Two 503s: still tried. Third: skipped for 30s. After expiry one more failure: 60s. A success resets to zero.
- **Quota hint.** A Groq success with `x-ratelimit-remaining-requests: 0` and `x-ratelimit-reset-requests: 2m59.56s`: the next request skips that candidate with zero calls for 2m59.56s.
- **Exhaustion.** All candidates cooling with known times: 429, `Retry-After` = earliest, rounded up. Any candidate failing without a known time: 503 `no_candidate_available`. The message names every candidate and reason, is under 2 KiB, and contains neither key nor upstream error text.
- **Zero-spend.** Config table: `openrouter/x` (no `:free`) in a default tier fails; with `allow_spend: true` passes; `gemini/x` without `free_tier` fails; `free_tier` on `openrouter` fails; `ollama/*` and `mock/*` pass.
- **Headers.** After `a` (429 with `Retry-After: 7`) and `b` success, the response has no `Retry-After` and names `b`.
- **Compatibility.** The OpenAI Python SDK calling `spillway/demo` against the mock gets `echo`'s answer non-streaming and streaming; on exhaustion it raises `RateLimitError` or `InternalServerError` with the Spillway message.
- **Security.** Provider keys and local keys absent from exhaustion bodies, skip logs, access logs and SSE bytes across the whole scenario table.
- **Concurrency.** 50 parallel requests across a tier while candidates fail and recover, under `-race`, with no data race and every request answered.
- **Unchanged.** Every v0.1 test passes unmodified except the virtual-model 404 test for `spillway/<tier>`; a config without `tiers` behaves exactly as v0.1.

## Risks

1. **Wrong attestation spends money.** A Gemini key whose project has billing enabled is charged at paid rates while Spillway believes it is free. Mitigation: explicit `free_tier: true` per provider, a startup log line, ADR 0005 and docs. Spillway cannot verify this; the plan does not claim it can.
2. **Spillover burns quota faster.** Each spilled request spends one request on every failing candidate before it. Bounded by tier length and cut down sharply by cooldowns after the first failure.
3. **Slow failure.** A provider that times out costs its full `timeout` (default 120s) before spilling. Mitigation: per-provider `timeout` already exists; a separate first-byte timeout is deferred until it is measured as a problem.
4. **Capability mismatch.** A tools or vision request can reach a model without that capability; its 400 does not spill. Documented, fixed by v0.3 capability detection.
5. **Shared OpenRouter free cap.** The 50/1000 per-day cap is account-wide; v0.2 learns it one model at a time (one 429 per `:free` candidate). Acceptable; provider-wide quota awareness arrives with declared limits in v0.4.
6. **State lost on restart.** Cooldowns reset; the first request after a restart rediscovers a limit with one 429. Persistence is v0.4.
7. **Heterogeneous responses.** Clients asking for `spillway/free` may get `id` and `model` formats from different providers across calls. Documented; OpenAI SDKs do not depend on them.
8. **Unverified fixture shape.** The Gemini `RetryInfo` body is modelled from documentation; a mismatch only loses the retry time (falls back to backoff), never correctness.

## Self-review

Gaps found and closed while writing:
- Without pulling `spillway/<tier>` forward, v0.2 tiers would be unreachable by clients; Decision 3.
- `Retry-After` from a failed attempt would leak onto a later success; headers are reset per attempt and tested.
- An unbounded tracker map if direct references were tracked from client input; the tracker only knows configured candidates.
- The two SSE gaps would turn a spillable first-event error into a corrupted success; ticket 1 is a prerequisite of streaming spillover.

Cut as overengineering:
- Half-open probe state, provider-wide transport breakers, configurable cooldown constants, a `router` package, catalog pricing verification, local request counting, a two-form tier syntax, an `x-spillway-route` header.
- What remains new: one package (`quota`, one type, two methods), one config section, one loop in the chat path.

Nothing open; see Decisions.

## Decisions

Resolved 2026-10-14: every decision below was accepted with its recommended option.

1. **Tiers are zero-spend by default; `allow_spend: true` opts out.** Alternative: spending allowed by default, `zero_spend: true` opts in. Recommended: default zero-spend, because silent spending is the one failure a free-first gateway must not have. ADR 0005.
2. **Free eligibility is a stated rule plus user attestation for Groq and Gemini.** Alternatives: exclude Groq and Gemini from zero-spend tiers entirely (safe but removes the two best free tiers), or treat every provider as free (unsafe). Recommended: attestation via `free_tier: true`. ADR 0005.
3. **`spillway/<tier>` and its `/v1/models` listing move from v0.3 to v0.2.** `auto`, capabilities and `x-spillway-route` stay in v0.3. Recommended: yes; otherwise tiers cannot be used. CONTEXT section 11 updated.
4. **Spillover classes: 429, 402, 5xx, transport, timeout, 401/403, 404 spill; 400/413/422 do not; commit point is the first byte to the client.** Recommended as listed. ADR 0006.
5. **Basic quota awareness is reactive (`Retry-After`, Gemini `retryDelay`) plus Groq header hints; declared limits and counting wait for v0.4.** Recommended, because in-memory daily counts reset on restart.
6. **Exhaustion status: 429 with `Retry-After` when every candidate has a known resume time, otherwise 503 `no_candidate_available`.** Recommended; both are retried by OpenAI SDKs.
7. **Direct model references are untouched by tiers and the tracker.** Recommended; keeps v0.1 semantics exact.
