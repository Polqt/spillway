# v0.4 Observability and Cost Control

Status: complete; shipped in v1.0.0; approved (2026-10-15; all eight decisions accepted as recommended, with one correction: failed provider attempts are not assumed to cost $0; ADRs 0009 to 0013 accepted)
Milestone: v0.4

## Goal

A developer can see what their client apps sent through Spillway, where each request went and why, what it probably cost, and whether a local spending cap is holding.
Usage and routing metadata land in a local SQLite file, a small embedded dashboard reads it, budgets stop paid models once an estimated cap is reached, and an opt-in exact cache serves repeated requests without a provider call.
A config without the new sections behaves exactly like v0.3: no file is created, no header changes, no body changes.

## Current state (inspected 2026-10-15, HEAD b0d672c)

- v0.3 is complete: `internal/router` plans `auto` and `spillway/<tier>`; `internal/api/chat.go` (521 lines) runs the spillover loop in `servePlan` and the direct path in `ServeHTTP`.
- `internal/api/middleware.go` already collects a per-request `requestRecord` (client app, provider, model, tier, route, attempts, stream, err) for one access-log line. It is the natural seam for usage records.
- Non-streaming responses are relayed verbatim as `ChatResponse.Body`; usage is not parsed out of them today.
- Streaming chunks already carry `ChatChunk.Usage` when the provider sends it, but providers only send usage when the request sets `stream_options.include_usage`, and Spillway forwards the body verbatim, so most streams carry no usage.
- `config.rejectFutureSections` rejects `budgets` and `cache` as v0.4; tests assert it.
- The ADR 0005 zero-spend rule lives in `config.isZeroSpendEligible` (unexported).
- `quota.Tracker` exposes `Available` and `Observe` only; there is no snapshot for a dashboard.
- Fixtures: Groq and mock responses carry `usage`; the OpenRouter fixtures carry no `usage`, no `usage.cost` and no catalog `pricing`. Every OpenRouter field shape below must be re-checked against current OpenRouter docs when its ticket starts.
- `go.mod` has one dependency (`go.yaml.in/yaml/v3`). `modernc.org/sqlite` latest is v1.60.1 (2026-09-29, `go 1.26.0`), old enough to pin under the two-week rule.

## Critical review of the proposed scope

The scope as asked is sound, but six parts of it conflict with existing decisions or with "minimal and testable" if taken literally.
Each is resolved below and listed again under Decisions.

1. **Exact cache in SQLite would store responses on disk.** That breaks "no prompt or response storage by default" the moment cache is on, and a cache file outlives the process. The cache is in memory only, opt-in, bounded by bytes, and gone on restart. Nothing prompt- or response-shaped ever reaches disk in v0.4.
2. **`on_exceed: cheap_only | block` (CONTEXT section 7) does not fit zero-spend tiers.** Free models cost nothing, so blocking them protects no money, and "cheap" has no definition. A budget makes paid models unavailable once reached; free models keep serving. `on_exceed` is dropped.
3. **Catalog discovery as a runtime capability source would change v0.3 routing.** Under ADR 0007, `auto` skips undeclared models for requests with requirements; a catalog that silently declares them would change which model serves, add startup network calls, and make routing depend on a remote list. Discovery becomes an explicit `spillway catalog` command that prints suggested `models:` and `pricing:` YAML for the user to review and paste. Declarations stay the only routing source.
4. **"Enforceable" budgets cannot be exact.** Spillway sees cost only after a response, estimates it from token counts and user prices, and cannot see spend from other tools on the same provider account. Budgets are a soft cap on Spillway-observed estimated spend, stated as such in the ADR, the dashboard and the docs.
5. **A budget with an unpriced paid model is not enforceable.** When a budget is set, every paid model must have a price source, or Spillway refuses it (fail closed), instead of counting it as free.
6. **A dashboard is a new authenticated surface.** Browser navigation cannot send a bearer header, and loopback is not a trust boundary (ADR 0003). The page shell is static and holds no data; its script asks for a local key and calls `/api/*` with it. Only local keys marked `dashboard: true` may read usage.

## Scope

In (MVP):
- `store:` config: SQLite file path and retention; opt-in.
- `internal/store`: `modernc.org/sqlite`, embedded forward-only migrations, one writer, request and attempt records, bounded queries, retention pruning.
- Usage capture for every chat request: tokens from non-streaming bodies and stream usage chunks, route reason, skips, attempts, status, latency, cache outcome.
- Stream usage capture: inject `stream_options.include_usage` upstream when the store is on and the client did not ask, and strip the injected usage-only chunk before relaying.
- `pricing:` config: user-declared USD per million input and output tokens per model reference.
- Cost estimation in integer micro-USD, with a recorded cost source.
- `budgets:` config: `daily_usd` and `monthly_usd`, UTC periods, enforced on paid models across direct, tier and `auto` requests.
- `cache:` config: in-memory exact cache, per client app, non-streaming only, TTL and byte bound; `x-spillway-cache` header when enabled.
- `/api/usage`, `/api/decisions`, `/api/budget`, `/api/quotas`, readable only with a `dashboard: true` local key.
- `/dashboard`: embedded static page in `apps/spillway/web/` (ADR 0004), no external assets, strict CSP.
- `spillway catalog`: explicit, read-only discovery from configured providers that publish usable fields; prints suggestions, changes nothing.
- ADRs 0009 to 0013, GLOSSARY, CONTEXT and example config updates.

Deferred:
- Prompt and response logging (`logging.bodies`): needs its own ADR on redaction and retention; not in v0.4.
- Semantic cache: v0.5 at the earliest, since it needs embeddings; `cache.semantic` is rejected.
- Streaming cache replay: store-and-replay of SSE chunks; later, if needed.
- Per-client-app budgets and per-app caps: after v0.4, when a real case appears.
- Budget reservations (pre-charging an estimate per in-flight request to bound overshoot): later; v0.4 documents the overshoot.
- Catalog data as a runtime routing or pricing source, and periodic catalog refresh: needs a new ADR amending 0007.
- Gemini catalog: the OpenAI-compatible list has no capability or price fields (ADR 0001); never via that endpoint.
- Cached-input, reasoning, image, audio and per-request pricing dimensions: v0.4 prices input and output tokens only.
- Currencies other than USD, provider billing APIs, invoice reconciliation: not planned.
- Multiple Spillway processes sharing one database file: unsupported; documented.
- A response cost header (`x-spillway-cost`): later, if clients ask.

## Design

### Config

```yaml
server:
  api_keys:
    - { name: my-app, key: "${SPILLWAY_KEY}" }
    - { name: me, key: "${SPILLWAY_ADMIN_KEY}", dashboard: true }   # may read /api/*

store:
  path: ./spillway.db        # opt-in; absent means no file and no usage records
  retention: 90d             # default 90d; requests older than this are pruned

pricing:                     # USD per million tokens; the only price source besides provider-reported cost
  openrouter/anthropic/claude-sonnet-4.5: { input_usd_per_mtok: 3.00, output_usd_per_mtok: 15.00 }

budgets:                     # requires store; soft caps on estimated spend, UTC periods
  daily_usd: 1.00
  monthly_usd: 5.00

cache:
  exact: true                # opt-in, memory only
  ttl: 1h                    # 1s to 24h
  max_mb: 64                 # 1 to 1024; entries over 1 MiB are not cached
```

Validation (each error names the YAML path and the fix):
- `store.path` is a file path whose directory exists; `retention` is 1d to 3650d.
- `budgets` requires `store` ("budgets need store.path so spend survives restarts"); each limit is positive with at most 6 decimals; at least one limit is set.
- With `monthly_usd`, `store.retention` must be at least 35d; with `daily_usd`, at least 2d.
- `budgets.on_exceed` fails with "removed: budgets always stop paid models and never free ones (ADR 0010)".
- `pricing` keys parse as model references with a configured provider; both prices are present, non-negative, at most 10000.
- With a budget set, every model in an `allow_spend` tier that is not zero-spend eligible (ADR 0005) must have a `pricing` entry.
- `cache.semantic` fails with "not supported"; `cache` keys other than `exact`, `ttl`, `max_mb` fail.
- `dashboard` on a local key is a boolean.
- `check` prints the new sections; prices and limits print, keys stay redacted.

`pricing` is a separate section, not a field on `models:`, because a capability declaration must be complete (ADR 0007) and must sit in a tier, while a price is also needed for direct references.

### Paid model

A model reference is **paid** when the ADR 0005 rule does not make it zero-spend eligible: not `ollama` or `mock`, not an OpenRouter `:free` model, not a `free_tier: true` Groq or Gemini provider.
The rule moves out of `config` into one exported function both `config` and `budget` call, so the two can never disagree.
Only paid models are charged or blocked; free models record cost 0 with source `free`.

### Usage records (internal/store)

```go
// Request is the metadata of one chat request. It never holds a key, a
// header value, a prompt, a response or provider error text.
type Request struct {
    At               time.Time
    ClientApp        string
    RequestedModel   string // as sent, at most 256 bytes, non-printable replaced
    Route            string // the x-spillway-route value
    Tier             string
    Provider, Model  string // the serving candidate, empty when none served
    Status           int
    ErrorKind        string // closed set: rate_limited, budget_exceeded, ...
    Stream           bool
    Cache            string // "", hit, miss, bypass
    LatencyMS        int64
    PromptTokens     int64
    CompletionTokens int64
    UsageSource      string // reported, estimated, none
    CostMicroUSD     int64
    CostSource       string // reported, declared, free, unknown, none
    Skips            []Skip     // router skips and their fixed-word reasons
    Attempts         []Attempt  // at most 16: provider, model, outcome kind, latency, tokens, cost and their sources
}

func Open(ctx context.Context, o Options) (*Store, error) // migrates, enables WAL, starts the pruner
func (s *Store) Record(ctx context.Context, r Request) error
func (s *Store) Usage(ctx context.Context, q UsageQuery) ([]UsageRow, error)       // grouped totals
func (s *Store) Recent(ctx context.Context, q RecentQuery) ([]Request, string, error) // cursor page
func (s *Store) SpendSince(ctx context.Context, t time.Time) (int64, error)
func (s *Store) Close() error
```

- Tables: `requests` (indexed on time) and `attempts` (foreign key to request). Skips are a bounded JSON column built only from fixed-word reasons.
- Migrations are embedded SQL with `PRAGMA user_version`; a database newer than the binary is refused with a message naming both versions.
- One connection for writes (SQLite allows one writer), WAL mode, `busy_timeout`; the file is created with mode 0600.
- `Record` runs after the response completes, on a context detached from the request with a 2 s timeout, so a client disconnect still records its row.
  A write failure is logged as an error with a stable key and counted for the dashboard; serving continues, and the in-memory budget is still charged.
  Writes stay synchronous until a measurement says otherwise; a local gateway at tens of requests per second is well inside SQLite's single-writer throughput.
- The pruner is one goroutine owned by `Store`, stopped by `Close`; it deletes rows older than `retention` at start and every hour.
- `Open` failing (bad path, locked file, newer schema) stops `serve` at startup.

### Usage capture (internal/api)

- `chatHandler` gains a consumer-side `usageRecorder` with `Record(ctx, store.Request)`. When the store is off it is nil and nothing changes.
- `requestRecord` grows the fields above; `servePlan` appends each attempt and seeds skips from `plan.Skipped`.
- Non-streaming: a small decode of `usage` (and OpenRouter's `usage.cost`, if present) from the response body, after it is written.
- Streaming: the last chunk with `Usage` wins.
  When the store is on, the body has `stream: true`, and the client did not set `stream_options.include_usage`, the upstream body gets `"stream_options":{"include_usage":true}` and the usage-only chunk (`choices: []`) is not relayed.
  Clients that asked for usage get it unchanged.
  With the store off, bodies are forwarded byte for byte as in v0.3.
- No usage reported (provider ignores the option, client disconnect, stream error): completion tokens are estimated as `ceil(relayed content bytes / 3)` and prompt tokens from the v0.3 size estimate times 2, with `usage_source: estimated`.
  These divisors overestimate on purpose, because a budget should err toward stopping early; the router's estimate underestimates on purpose, because a filter should err toward trying.

### Cost (internal/budget)

Cost is computed per attempt, successful or failed; a request's cost is the sum of its attempts.
For each attempt, the first source that applies:

| Source | When | `cost_source` |
|---|---|---|
| Free | the attempted model is zero-spend eligible | `free` |
| Provider-reported | OpenRouter returns `usage.cost` (shape to verify) | `reported` |
| Declared price | `pricing:` entry and token counts (reported or estimated): `ceil(prompt × in + completion × out) / 1e6` in micro-USD | `declared` |
| Unknown | paid model without a price, budgets off | `unknown` (counted 0, shown as unknown) |

- Integer micro-USD everywhere; prices are converted once at config load. No floats in sums.
- A failed attempt on a paid model is never assumed free, because some providers bill partially processed requests and Spillway cannot see which did.
  If the failure carries usage, it is priced like a success.
  Otherwise it is charged its estimated prompt tokens and no completion tokens, with `usage_source: estimated`; this may overcount a request the provider rejected before processing, which is the safe direction for a budget.
  A stream that failed after the commit point is also charged its estimated relayed completion tokens.
- Skipped candidates (cooling, budget, capability) were never sent and cost nothing; they are skips, not attempts.
- Cache hits cost 0.

### Budgets (internal/budget)

```go
func NewGate(o GateOptions) (*Gate, error) // limits, clock, seeded spend from store.SpendSince
func (g *Gate) Allow(ref providers.ModelRef) (ok bool, resetAt time.Time)
func (g *Gate) Charge(at time.Time, costMicroUSD int64)
func (g *Gate) Status() Status // limits, spent, reset times, for /api/budget
```

- In-memory daily and monthly totals behind a mutex, seeded at startup from the store, rolled over at UTC midnight and month start using the injected clock.
- `Allow` is true for free models always, and for paid models while every configured period is under its limit.
- Tier and `auto`: a blocked paid candidate is skipped like a cooling one, reason `budget exceeded (resets in 3h12m)`, with `until` set to the earliest reset. If every eligible candidate is cooling or blocked, v0.2 exhaustion answers 429 with `Retry-After`; the header grammar is unchanged (`exhausted (n eligible)`).
- Direct reference to a blocked paid model: 429, `type: insufficient_quota`, `code: insufficient_quota`, the shape OpenAI uses for an exhausted account, with `Retry-After` and a message naming the budget and its reset time.
- Direct reference to an unpriced paid model while budgets are set: 400 `invalid_request_error`, code `model_price_unknown`, message naming the `pricing.<ref>` entry to add. Tier models were already checked by config.
- Soft cap: the check happens before a request and the charge after it, so concurrent in-flight requests can overshoot by at most their own cost. Documented, tested, not hidden.

### Exact cache (internal/cache)

- Memory only. Key: SHA-256 of client app name, a zero byte, and the raw request body bytes. One app can never read another app's entries.
- Lookup after body decode and plan, before any candidate; a plan error is never cached.
- Stored only for non-streaming 200 responses up to 1 MiB, with the original `x-spillway-provider`, `x-spillway-model` and `x-spillway-route` values, so a hit replays the same headers and ADR 0008's route grammar is untouched.
- Streaming requests and requests with header `x-spillway-cache: bypass` skip lookup and store.
- Response header `x-spillway-cache: hit | miss | bypass` is set only when the cache is enabled, so v0.3 responses are unchanged when it is off.
- LRU eviction by total bytes; expiry by TTL on the injected clock. A hit is recorded with `cache: hit`, its original token counts and cost 0.
- Byte-exact keys mean reordered JSON keys miss; that is what "exact" means and it keeps the key cheap and unambiguous.

### Dashboard API

All under the existing Host check and auth middleware, and only for `dashboard: true` keys (others get 403 `permission_denied`). Errors use the OpenAI shape. Every response sets `Cache-Control: no-store`.

- `GET /api/usage?since=&until=&group=provider|model|client_app|day`: grouped requests, errors, cache hits, tokens, cost (micro-USD and a decimal string), and how many rows were estimated. Range at most 400 days; `group` from the closed set.
- `GET /api/decisions?limit=&before=`: recent requests newest first, with route, skips and attempts; `limit` 1 to 200, opaque cursor.
- `GET /api/budget`: limits, spent, remaining, reset times, and whether any spend was estimated or unknown.
- `GET /api/quotas`: per candidate, cooldown until, reason and breaker state; needs a read-only `Tracker.Snapshot`.

### Dashboard page (apps/spillway/web)

- A Go package that embeds one HTML file, one CSS file and one JS file and exports an `http.Handler` (ADR 0004); `internal/cli` passes it to `api.Options.Dashboard`.
- `GET /dashboard` serves the shell with no data; it is behind the Host check but not auth, because a browser navigation cannot send a bearer header.
- The script asks for a local key, keeps it in `sessionStorage`, and calls `/api/*` with `Authorization: Bearer`. No cookie, so no CSRF surface.
- Headers: `Content-Security-Policy: default-src 'self'; frame-ancestors 'none'; base-uri 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`. No inline script, no external font or CDN, no framework.
- All data is written with `textContent`; model names come from clients and are untrusted.
- Views: today and month spend against budget, totals by provider and model, recent decisions with route reasons and skips, current cooldowns. Polls every 10 s. Every cost reads "est." with a link to the limitations.

### Catalog discovery (`spillway catalog`)

- Explicit subcommand: loads config, contacts only the configured providers, prints YAML to stdout, writes nothing, changes no routing.
- Sources: OpenRouter `GET /models` (pricing, `supported_parameters`, `architecture.input_modalities`, `context_length`); Ollama `POST /api/show` per configured model (`capabilities`, context length; price 0); Groq `GET /models` (`context_window` only). Gemini and mock: skipped with a note.
- Output: a `models:` block and a `pricing:` block for models in the user's tiers and pricing entries, each line commented with its source, plus a diff against current declarations (`# declared [tools], catalog adds vision`).
  It warns when a configured OpenRouter `:free` model has non-zero catalog pricing, closing the ADR 0005 follow-up as a warning rather than a runtime check.
- Bounded: 8 MiB per response, provider timeouts, each provider's key sent only to that provider. Output contains no key.

### Request lifecycle after v0.4

1. Authenticate, decode, plan (v0.3).
2. Cache lookup when enabled; a hit answers and records.
3. Direct: budget gate, then provider. Virtual: for each eligible candidate, tracker, then budget gate, then provider, with v0.2 spillover.
4. After the response: compute usage and cost, charge the budget, cache a cacheable 200, record to the store, write the access log.

### Hard-rule check

- No quota evasion: budgets and cache only reduce calls; spillover rules are unchanged; one key per provider.
- No credential collection: no new credential; `dashboard: true` marks an existing local key.
- Secrets never leak: the store, the `/api/*` responses, the dashboard and `catalog` output hold no keys; tests scan the database file bytes, API bodies and catalog output for every configured key.
- Single binary, no cgo: `modernc.org/sqlite` is pure Go; `CGO_ENABLED=0 make build` is part of the store ticket's acceptance; the dashboard is embedded.
- Local by default: no new listener; `/dashboard` and `/api/*` sit behind the same Host check and auth; the only new outbound calls are `catalog`'s, to configured providers, on explicit command; no telemetry.
- OpenAI compatibility: `/v1/*` shapes unchanged; budget errors reuse `insufficient_quota`; the stream usage option is injected only with the store on and its extra chunk is stripped; new headers are additive and off by default.

## Limitations to state in docs and the dashboard

- **Cost is an estimate.** Token counts are the provider's when reported, otherwise overestimates. Prices are the user's declarations and go stale. Cached-input discounts, reasoning-token pricing, image and audio pricing, per-request fees, minimum charges, taxes and currency conversion are not modelled.
- **Provider billing is invisible.** Spillway cannot read invoices, account balances or plan state. A Groq or Gemini free-tier attestation (ADR 0005) is still only the user's claim; a project that silently gains billing is counted as free.
- **Budgets are soft and local.** Overshoot by in-flight requests is possible; spend made outside this Spillway process (other tools, other machines, a second Spillway) is not counted; deleting the database resets the count.
- **Usage may be missing.** Providers that ignore `stream_options.include_usage`, client disconnects and mid-stream failures fall back to estimates, marked as such.
- **Failed attempts are charged by estimate.** Whether a provider bills a failed request is not observable; Spillway charges a failed paid attempt its estimated prompt cost, which can overcount a request that was rejected before processing and undercount one that generated hidden output before failing.
- **Catalog data is advisory.** It reflects what a provider publishes at the moment `catalog` runs; coverage is partial (no Gemini, Groq context only).

## Security considerations

- No prompt, response, header value or provider error text is written to disk; the cache holds responses in memory only, per client app, and is opt-in.
- The database holds client app names, model references, route reasons, token counts and costs: metadata that still reveals usage patterns, so it is created 0600 and documented as sensitive.
- Client-supplied model strings reach the database and the dashboard: stored length-bounded, queried with parameters, rendered with `textContent`, under a strict CSP. A test feeds `<script>` and quote characters through a model name.
- `/api/*` requires a `dashboard: true` key; a chat-only key gets 403. Host check applies to `/dashboard` and `/api/*`, which blocks DNS rebinding as in ADR 0003.
- The local key lives in `sessionStorage`; the CSP and no-inline-script rule are what keep an injected script from reading it.
- All queries and results are bounded: date range, page size, group set, retention, cache bytes, catalog response size.
- Cache timing reveals whether the same app sent the same body before; keys are per app, so it reveals nothing across apps.
- `catalog` sends each provider key only to its own provider's configured `base_url`, with the existing https-unless-loopback rule.

## Acceptance criteria and offline test scenarios

All offline: the mock provider, in-test fake providers, `httptest.Server` fixtures, `t.TempDir()` databases, `testing/synctest` for time.

- **Unchanged without new config.** A v0.3 config: no file created, no `x-spillway-cache` header, request bodies forwarded byte for byte (streaming included), every v0.3 test passes unchanged.
- **Every request recorded.** Direct, tier, `auto`, cache hit, plan error, exhaustion, upstream 400, client disconnect: one row each, with route, attempts and skips matching the response headers.
- **No content on disk.** After a run with distinctive prompt and response text and every configured key, a byte scan of the database, its WAL and SHM files finds none of them.
- **Usage sources.** Groq fixture usage is `reported`; an injected-usage stream is `reported` and the client sees no usage chunk; a client that asked for usage sees it; a stream without usage and a disconnected stream are `estimated`.
- **Cost by worked example.** 1,234 prompt and 567 completion tokens at $3 and $15 per Mtok is 12,207 micro-USD; free models cost 0 with source `free`; an OpenRouter fixture's `usage.cost` wins over a declared price; a paid candidate failing with 503 and no usage before a free candidate serves is charged its estimated prompt cost with source `declared` and `usage_source: estimated`, and the request's cost is that sum.
- **Budget blocks paid only.** Monthly cap reached: a paid tier candidate is skipped `budget exceeded`, the free candidate serves; `auto` stays on free tiers; a direct paid reference gets 429 `insufficient_quota` with `Retry-After`; a direct free reference serves.
- **Budget rollover and restart.** Spend seeded from the store after restart; daily total resets at UTC midnight; monthly at month start.
- **Fail closed.** Budget set and an unpriced paid model in an `allow_spend` tier: `check` refuses with the `pricing.<ref>` fix; direct unpriced paid reference: 400 `model_price_unknown`.
- **Soft cap is bounded.** 50 concurrent paid requests at the edge of the cap: total charged exceeds the cap by at most the sum of those requests' costs, and the next request is blocked.
- **Cache.** Same app and body: second call hits, zero provider calls, identical body and headers plus `x-spillway-cache: hit`; another app with the same body misses; streaming and `bypass` never hit; TTL expiry and byte-bound eviction under `synctest`.
- **Dashboard access.** No key: 401; chat-only key: 403; dashboard key: 200; foreign `Host` on loopback: rejected before auth; `/dashboard` shell contains no usage data.
- **Dashboard safety.** CSP and `nosniff` headers present; HTML has no inline script; a model name of `"><script>alert(1)</script>` is stored bounded and returned as JSON text.
- **API bounds.** `limit=10000` and a 10-year range are 400s with the OpenAI shape; cursor pages are stable under concurrent inserts.
- **Catalog.** OpenRouter, Ollama and Groq fixtures produce the expected YAML; Gemini is skipped with a note; a `:free` model with a non-zero price warns; output contains no key; no request reaches an unconfigured host.
- **Race and bounds.** 50 parallel mixed requests with store, budget and cache on under `-race`: no race, row count equals request count.
- **Single binary.** `CGO_ENABLED=0 go build ./...` succeeds; `go.mod` gains only `modernc.org/sqlite` and its requirements.

- stop and restart `serve` and see month spend preserved.

## Risks

1. **Dependency weight.** `modernc.org/sqlite` is large and grows the binary and module graph. Mitigation: it is the documented choice, it keeps cgo out, and ticket 2 records the size cost.
2. **Usage injection changes forwarded bodies.** Only with the store on; some providers may reject or ignore `stream_options`. Ticket 4 verifies each preset against its docs and fixtures, and a provider that rejects it gets a per-preset opt-out; ignored means estimated usage.
3. **Stale prices undercount spend.** Mitigation: OpenRouter reported cost where available, `catalog` diffs, "est." everywhere.
4. **Budget overshoot under concurrency.** Bounded and documented; reservations deferred.
5. **Store write failures.** Logged and counted, budget still charged in memory; a full disk degrades history, not enforcement until restart.
6. **Cache returns stale or non-deterministic answers.** Opt-in, TTL-bounded, per app, with a bypass header; documented that temperature is ignored.
7. **Dashboard is a browser surface.** Strict CSP, no inline script, `textContent`, explicit dashboard keys, Host check.
8. **`chat.go` grows again.** Cache, gate and recording add to a 521-line file. Ticket 3 moves record assembly into its own file in `api`, and ticket 6 adds the gate as one more availability check beside the tracker, not a new loop.

## Self-review

Gaps found and closed:
- A cache in SQLite would have broken the no-content-on-disk rule; it is memory only.
- Budgets without a store would silently reset on restart; budgets require the store.
- Monthly budgets with short retention would seed from partial data; retention is validated against the budget period.
- Budget-blocked candidates without a reset time would turn "all cooling" into 503; the gate returns the period reset as `until`.
- Streams without usage would make budgets blind; usage is injected when the store is on, with overestimates as the fallback.
- Assuming failed attempts cost $0 would undercount providers that bill partially processed requests; failed paid attempts are charged an estimate (correction at approval).
- A dashboard key check was missing from the brief; any local key could have read every app's usage.

Cut as overengineering:
- Async write queue, rollup tables, reservations, per-app budgets, catalog refresh, streaming cache, semantic cache, cost header, a chart library.
- What remains new: three packages (`store`, `budget`, `cache`), one embedded web package, four config sections, one subcommand, four JSON endpoints.

## ADRs

Written and accepted with this plan:

- **0009 Local usage store.** SQLite via `modernc.org/sqlite`, opt-in by `store.path`; metadata only, never prompts, responses, headers or provider text; retention; one process per file; schema versioning.
- **0010 Cost estimates and local budgets.** Paid model definition from ADR 0005; per-attempt source precedence; failed paid attempts never assumed free; micro-USD; soft cap on observed estimated spend; UTC periods; free models never blocked; fail closed on unpriced paid models; `insufficient_quota` errors; stream usage injection with the store on. Amends the CONTEXT `on_exceed` design.
- **0011 Exact response cache.** Memory only, opt-in, per client app, byte-exact key, non-streaming 200s, replayed route headers, `x-spillway-cache` only when enabled.
- **0012 Dashboard access.** Static shell plus bearer from script, `dashboard: true` keys, Host check, CSP and no external assets; changing to cookies or unauthenticated data needs a new ADR.
- **0013 Catalog discovery is advisory.** `spillway catalog` prints suggestions on explicit command; declarations stay the only routing capability source (ADR 0007) and pricing comes from `pricing:` or provider-reported cost; using catalog data at runtime needs a new ADR.

## Decisions

Resolved 2026-10-15: every decision below was accepted with its recommended option.

1. **Store is opt-in via `store.path`.** Alternative: on by default at a fixed path. Recommended opt-in, because v0.3 configs must not start creating files, and `examples/` and later `spillway init` turn it on.
2. **Exact cache is memory only.** Alternative: SQLite-backed, surviving restarts. Recommended memory, because a disk cache stores responses and breaks the no-content-on-disk default for little gain on a dev gateway.
3. **Budgets stop paid models only, as a soft cap; `on_exceed` is dropped.** Alternative: keep `cheap_only | block`. Recommended as stated, because blocking free models saves nothing and "cheap" is undefined.
4. **Fail closed on unpriced paid models when a budget is set.** Alternative: count them as unknown and let them through. Recommended fail closed, since a budget that ignores some paid traffic is not enforceable.
5. **Inject `stream_options.include_usage` when the store is on, and strip the injected chunk.** Alternative: never touch bodies and estimate stream usage. Recommended injection, because estimates alone make streamed spend unreliable; with the store off, bodies stay verbatim.
6. **Dashboard data needs a `dashboard: true` local key, sent as a bearer by the page script.** Alternatives: any local key, or a cookie session. Recommended as stated: least privilege, and no CSRF surface.
7. **Catalog discovery is an explicit, advisory `spillway catalog` command.** Alternatives: a runtime source with declarations taking precedence, or defer catalog entirely. Recommended advisory, because a runtime source changes v0.3 routing and adds startup network dependence. If v0.4 must shrink, ticket 10 is the one to defer; nothing depends on it.
8. **USD only, integer micro-USD, UTC calendar periods.** Alternative: a configurable time zone for periods. Recommended UTC for v0.4; a `budgets.timezone` can be added later without changing stored data.
