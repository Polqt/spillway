# v1.2 provider-instance manual verification

This checklist covers provider-instance configuration and CLI behavior without contacting an upstream provider.
Use a temporary config and fake credentials only.

## Local Ollama configuration and CLI checks

1. Start local Ollama, then run `spillway init -yes -providers ollama -config <temp-config>`.
2. Run `spillway check -config <temp-config>` and `spillway provider list -config <temp-config>`; confirm output contains no credential values.
3. Run `spillway provider add gemini --name gemini-research --key-env GEMINI_RESEARCH_API_KEY --dry-run -config <temp-config>`.
4. Confirm the preview shows the safe alias and environment-variable reference, hides credential values and quota-domain labels, and does not change the file.
5. Repeat with `--yes`; confirm a private backup is created, routes are unchanged, and the resulting config passes `spillway check`.
6. Run `spillway provider show gemini-research -config <temp-config>` and confirm it reports only safe instance metadata and environment-variable presence.
7. Set a virtual route containing two distinct Gemini aliases and confirm `spillway check` rejects the route with a secret-free message.
8. Set a virtual route with two models from one Gemini alias and a Groq alias; confirm the route validates and retains its declared candidate order.
9. Confirm the explicit model reference `gemini-research/gemini-2.5-flash` selects only that configured instance in the local fake-server test.
10. Confirm `auto` still follows `router.auto` and that an instance addition does not rewrite any route.

## Security and compatibility checks

- Use separate fake environment-variable names for instances and never pass provider credentials to these commands.
- Confirm unknown-scope cooldown behavior is provider-service-wide and expires within the configured retry clamp.
- Confirm a known provider-documented quota domain is shared only by instances carrying the matching verified opaque label.
- Confirm instance budgets restrict their selected instance and the aggregate process-wide budget remains the overall ceiling.
- Confirm API error bodies, route reasons, logs, list/show output and config output contain no key values or raw upstream bodies.
- Confirm OpenAI-compatible `/v1/*` request, response, streaming and error contracts remain unchanged.
- Do not use account changes or credential rotation to verify quota exhaustion behavior.

Live provider integration and policy-specific limit checks are not part of this offline checklist.
