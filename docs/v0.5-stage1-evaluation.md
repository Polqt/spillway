# Stage 1 deterministic routing evaluation

## Decision

The offline paired run verifies that the evaluation harness can compare current `auto` with opt-in rules mode.
It does not provide promotion evidence because the mock provider returns deterministic echoes, both arms use the same free model, and the prompt set contains only six prompt-level clusters.
Rules mode remains opt-in.
A live evaluation with paid or quality-capable models and at least two independent blinded raters is still required before recommending default enablement.

## Paired confidence intervals and gates

The paired prompt-cluster bootstrap sampled the six prompt IDs with replacement, retaining all 30 repeats and both arms for every sampled prompt.
It used 10,000 replicates and seed `20261016`.
The percentile 95% interval for p95 end-to-end latency regression (`rules p95 / current-auto p95 - 1`) was 0% to 50%.
The observed aggregate p95 regression was 50% (3 ms versus 2 ms).
The interval is highly discrete and noisy because there are only six prompt clusters and millisecond mock timings.

| Promotion gate | Result | Assessment |
|---|---|---|
| Mean cost at least 10% lower, with paired 95% savings interval above 0% | Both means were $0; savings and its interval are undefined. | Inconclusive; mock arms cannot evaluate cost reduction. |
| Upper bound for paired p95 latency regression at most 5% | Observed +50%; paired 95% interval [0%, +50%]. | Does not pass this mock run; timings are not live-model latency evidence. |
| Lower bound for mean paired quality difference above -0.2 | No blinded ratings were entered. | Not measured; mock echoes cannot be quality-rated as model answers. |
| Upper bound for severe-failure-rate difference at most +2 percentage points | No blinded ratings or adjudications were entered. | Not measured. |
| At least 95% known-cost coverage in each arm | 100% in both arms, all marked free. | Numeric gate passes for the mock-only run; it does not validate paid-model cost sources. |

No gate supports promotion, so deterministic routing stays opt-in as required by ADR 0014.
The latency result is recorded as a mock-run failure and must not be generalized to real providers.

## Reproduction

Start both local mock servers in separate terminals:

```powershell
go run ./apps/spillway serve -config examples/config.eval.yaml
go run ./apps/spillway serve -config examples/config.eval.rules.yaml
```

Run the paired evaluation with a local fixture key:

```powershell
$env:SPILLWAY_EVAL_KEY = "sk-test-spillway-evaluation"
go run ./apps/spillway eval -dataset examples/evaluation-prompts.v1.json -arms current-auto=auto@http://127.0.0.1:8080,rules=auto@http://127.0.0.1:8081 -repeats 30 -seed 20261016 -prices examples/evaluation-prices.mock.json -api-key-env SPILLWAY_EVAL_KEY -out .scratch/v0.5-smart-routing/evaluation-stage1-offline/run
Remove-Item Env:\SPILLWAY_EVAL_KEY
```

For promotion evidence, use the manual live-model protocol in [v0.5-evaluation.md](v0.5-evaluation.md), identical configured candidates and declared prices in both arms, a representative prompt corpus with substantially more prompt clusters, and two independent blinded raters.
