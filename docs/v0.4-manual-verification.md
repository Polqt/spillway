# v0.4 manual verification

This walkthrough uses the offline mock provider and verifies cache, streaming usage capture, dashboard access, catalog output and restart behavior.
The mock provider is always free, so its illustrative `pricing.mock/echo` entry cannot spend or exhaust the configured budget.
The paid-model budget and cached paid-answer behavior are exercised offline by `TestObservability_CachedPaidAnswerSurvivesBudgetAndMixedConcurrencyRecordsEveryRequest`.

## Start Spillway

From the repository root, run:

```shell
make mock
```

This creates `spillway-mock.db` in the current directory.
The example uses only fake local keys and makes no provider calls outside the mock provider.

## Check cache and streaming

Run the following request twice.
The first response should include `x-spillway-cache: miss`; the second should include `x-spillway-cache: hit`.

```shell
curl -i http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer sk-test-spillway-mock" \
  -H "Content-Type: application/json" \
  -d '{"model":"mock/echo","messages":[{"role":"user","content":"Cache me"}]}'
```

Use the OpenAI Python SDK to stream a completion.
The store causes Spillway to request usage upstream when the client did not request it, then hides the usage-only chunk from the client.

```shell
uv run --with openai python - <<'PY'
from openai import OpenAI

client = OpenAI(api_key="sk-test-spillway-mock", base_url="http://127.0.0.1:8080/v1")
stream = client.chat.completions.create(
    model="mock/echo",
    messages=[{"role": "user", "content": "Stream this"}],
    stream=True,
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="", flush=True)
print()
PY
```

## Check dashboard permissions and request history

Open `http://127.0.0.1:8080/dashboard` and enter `sk-test-spillway-dashboard`.
The page should show spend, totals, decisions and cooldowns.

The demo key can call chat but must receive 403 from dashboard APIs:

```shell
curl -i http://127.0.0.1:8080/api/decisions \
  -H "Authorization: Bearer sk-test-spillway-mock"
```

The dashboard key can inspect the stream record and its `reported` usage source:

```shell
curl http://127.0.0.1:8080/api/decisions \
  -H "Authorization: Bearer sk-test-spillway-dashboard"
```

## Check advisory catalog and restart persistence

In another terminal, run `spillway catalog -config examples/config.mock.yaml`.
It should print the mock skip note and no key material.

Read the monthly total from `/api/budget` using the dashboard key, stop the server, restart it with `make mock`, and read `/api/budget` again.
The mock total is zero because mock models are free; this confirms the persisted store opens while the in-memory response cache starts empty after restart.
The end-to-end test verifies that non-zero paid-model month spend seeds the budget after reopening the database.

## Verify nonzero paid spend without provider credentials

The mock scenario cannot hit a budget by design.
For a complete manual paid-budget check, use the local OpenAI-compatible fixture in `examples/manual_paid_provider.py` and `examples/config.manual-paid.yaml`.
The fixture binds only to loopback, accepts only its documented fake provider key and returns fixed two-token usage.

In one terminal, start the fixture:

```shell
python examples/manual_paid_provider.py
```

In a second terminal, start Spillway:

```shell
$env:OPENROUTER_API_KEY = "sk-test-openrouter-manual"
go run ./apps/spillway serve -config examples/config.manual-paid.yaml
```

Run the same direct paid request twice:

```shell
curl -i http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer sk-test-spillway-manual" \
  -H "Content-Type: application/json" \
  -d '{"model":"openrouter/manual-fixture","messages":[{"role":"user","content":"Paid fixture"}]}'
```

The first response should be a cache miss and charge 2 micro-USD; the second should be a cache hit with cost 0.
The SDK's different prompt must raise `RateLimitError` with `insufficient_quota`:

```shell
uv run --with openai python - <<'PY'
from openai import OpenAI, RateLimitError

client = OpenAI(api_key="sk-test-spillway-manual", base_url="http://127.0.0.1:8080/v1")
try:
    client.chat.completions.create(
        model="openrouter/manual-fixture",
        messages=[{"role": "user", "content": "A different paid fixture request"}],
    )
except RateLimitError as error:
    assert error.code == "insufficient_quota", error.code
    print("budget returned RateLimitError: insufficient_quota")
else:
    raise SystemExit("expected the reached budget to block the paid model")
PY
```

Read `/api/budget` with the dashboard key, stop and restart Spillway with the same config, and read it again:

```shell
curl http://127.0.0.1:8080/api/budget \
  -H "Authorization: Bearer sk-test-spillway-manual-dashboard"
```

The monthly spend should remain 2 micro-USD after restart.
The exact response cache is process-local, so repeating the original prompt after restart should be a cache miss and the reached budget should block it.

The offline end-to-end test also runs 50 parallel direct, tier and `auto` requests with store, budget and cache enabled under `-race`, and checks that every request has one stored row.

## Cost and budget notes

Costs are estimates and can differ from provider billing.
Failed paid attempts without usage are charged the estimated prompt cost.
Budgets are local soft caps and can overshoot by costs from requests already in flight.
See the limitations in [README.md](../README.md#usage-cost-budgets-and-dashboard).
