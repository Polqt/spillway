# v1.1.0 manual accessibility and first-run review

**Record prepared:** 2026-10-20

**Review status:** Owner-reported manual review completed on the `v1.1.0-rc.1` embedded and fallback builds on 2026-10-21.
Automated browser/axe checks are recorded separately as preliminary evidence and are not a substitute for this review.

## Procedure

### 1. Identify the exact builds and environment

Use the Windows release-candidate archive for the embedded dashboard and a Go-installed build from the matching RC source tag for the fallback dashboard.
Install the fallback build from the repository root:

```sh
git clone --branch v1.1.0-rc.1 --depth 1 https://github.com/Polqt/spillway.git
cd spillway
go install ./apps/spillway
```

Set `$spillwayExe` to the archive executable for the embedded pass.
For the fallback pass, set it to the Go bin executable (normally `(go env GOPATH)\bin\spillway.exe`; use `go env GOBIN` instead when set).
Use an absolute executable path because each test pass changes the working directory.
Invoke each executable with `& $spillwayExe`, not an ambiguous `PATH` lookup.
Run `& $spillwayExe version -verbose` and confirm its reported executable path and `dashboard_assets` value match the intended build.
Record the exact version/build fields in the results table.
Do not substitute a local development build for the RC.
Record the Windows edition/build, Microsoft Edge version, and Narrator version from the machine used.
Do not put config contents, local keys, or clipboard contents containing credentials in this record.

For each dashboard build, create a unique temporary working directory so the mock config and SQLite store are isolated from the repository and from the other dashboard pass.
Run that pass's commands from inside its working directory:

```powershell
$passDir = Join-Path $env:TEMP ("spillway-t11-embedded-" + [guid]::NewGuid())
New-Item -ItemType Directory -Path $passDir | Out-Null
Push-Location $passDir
& $spillwayExe init -yes -providers mock -store -config .\t11.yaml
& $spillwayExe check -config .\t11.yaml
& $spillwayExe serve -config .\t11.yaml
```

Use the archived executable for the embedded pass.
For the fallback pass, use the executable installed from the same RC tag and repeat in a new unique temporary working directory.
Open `http://127.0.0.1:8080/dashboard`; enter the local dashboard key from that private config only in the dashboard.
Keep the key out of notes, screenshots, issue comments, and this document.
Stop the server with Ctrl+C, return to the original directory with `Pop-Location`, then remove only that pass's temporary directory with `Remove-Item -LiteralPath $passDir -Recurse -Force`.
This removes the temporary config and its `spillway.db` store together.

### 2. Narrator and Edge dashboard flows

Run this list once against each build (embedded archive, then Go-installed fallback):

1. Start Narrator (`Win+Ctrl+Enter`) and Microsoft Edge.
   Navigate to `/dashboard` and connect using the private dashboard key.
   Confirm the field, Connect action, and connected/version announcement have useful names and are announced in a sensible order.
   Confirm an invalid key gives an announced error without exposing the key.
2. Navigate the provider status section.
   Confirm its heading and configured mock provider/status are announced, and that the text does not imply a reachability probe.
3. Navigate to the client example panel.
   On the embedded dashboard, select an example and activate **Copy example**; confirm success or failure is announced.
   On the fallback dashboard, expand an example, select its code, and copy it with the keyboard (the fallback is static and has no copy button).
   Paste locally and verify the result contains the local origin and `<LOCAL_APP_KEY>`, not the dashboard key; clear the clipboard/editor afterward.
   Do not save or share the pasted text.
4. Navigate to the playground.
   Submit a short harmless prompt to the mock provider.
   Confirm the request status, response, and route explanation are announced.
   Confirm the route explanation identifies the selected route/candidate and reason in understandable order.
5. Exercise **Cancel request**.
   If the mock response completes too quickly, use Edge DevTools Network throttling (for example, Slow 3G) before submitting, then activate Cancel while it is available.
   Confirm the cancellation is announced and the controls return to an operable state.
   If it cannot be exercised, record it as not covered rather than assuming it works.
6. Navigate to and activate **Forget dashboard key**.
   Confirm the disconnected state is announced, the access form is available again, and reconnecting works.

### 3. Keyboard-only, zoom, motion, and contrast

Repeat these checks on both dashboard builds.
Do not use a mouse during the keyboard-only pass.

- **Keyboard-only:** From page load, use Tab, Shift+Tab, Enter, Space, and arrow keys where a widget requires them.
  Confirm visible focus, logical order, the skip link/landmark navigation, operable tabs/details/forms/buttons, no keyboard trap, and that focus remains sensible after connect, copy, cancel, and forget.
- **200% zoom:** Set Edge zoom to 200%.
  Connect and inspect the client examples, provider status, playground, response, and route explanation.
  Confirm content remains readable and operable without horizontal page scrolling or clipped controls.
- **320 CSS px:** Use responsive design mode at 320 CSS px (record the viewport, not the device-pixel width).
  Repeat the same content/operation checks and confirm there is no horizontal page scrolling.
- **Reduced motion:** Enable Windows/Edge reduced-motion preference, reload, and confirm decorative/transitional motion is reduced while state changes and focus feedback remain perceivable.
- **Windows contrast themes:** Enable a Windows contrast theme (forced colors), reload, and check text, focus indicators, controls, tabs, status indicators, and route/status content for visibility and operability.
  Record the exact theme name.

### 4. Interactive `init` with Narrator

In Windows Terminal, start Narrator and create an isolated temporary working directory:

```powershell
$initDir = Join-Path $env:TEMP ("spillway-t11-init-" + [guid]::NewGuid())
New-Item -ItemType Directory -Path $initDir | Out-Null
Push-Location $initDir
& $spillwayExe init -config .\t11-interactive.yaml
```

Use Huh's accessible, line-oriented prompts to select only the `mock` provider and enable the local store/dashboard access.
Follow the numbered/text choices as announced; record any prompt that is not announced, has an unclear choice, or cannot be completed without a pointer.
Confirm the setup summary gives understandable next steps.
Then run `& $spillwayExe check -config .\t11-interactive.yaml`.
Verify the config was created without overwriting an existing file.
Do not read aloud, copy into notes, or record any generated key or config secret.
Return to the original directory with `Pop-Location` and remove only `$initDir` with `Remove-Item -LiteralPath $initDir -Recurse -Force` after the review.

### 5. Optional assistive technology

If available, repeat the key dashboard flows with NVDA + Firefox and/or VoiceOver + Safari.
Record each as **Run** or **Not run** with versions and findings.
These are optional and do not replace the required Narrator + Edge review.
